# monitors/ (display configurator)

- **`monitors/`** — the display configurator: `Monitors.qml` (the `FloatingWindow` + IPC), `MonitorsView.qml` (state, the layout bar, the `monitors.py` calls — two one-shot `Poll`s with `running: false`), `MonitorCanvas.qml` (drag-to-arrange), `MonitorInspector.qml` (mode/scale/rotation dropdowns) and `MonitorButton.qml`. **No `qmldir`** — no singletons, so the implicit directory import is enough. It owns the whole notion of named layouts; reach only ever sees one file. Non-obvious bits: (1) it is a **window**, like the music player, because a full-screen picker overlay swallows every click while mapped and this is a surface you sit in and resize; reach tiles it by the shared `org.quickshell` app_id, so a rule must narrow by the title `Displays`. (2) The canvas draws **layout entries and live outputs together**, distinguishing *not connected* (in the layout, nothing plugged in — peach) from *not in layout* (plugged in, unlisted — dimmed): that is what lets the desktop's arrangement be edited from the laptop, which is the whole point of separate files. An unlisted head is parked to the **right** of the arrangement rather than at 0,0, where it would sit on top of the first monitor. (3) A rotated head's `w`/`h` are its MODE, so every size question goes through `effW`/`effH` (and bounding boxes through `extent()`, which the canvas fit, the save normalisation and the unlisted-head parking share), which swap them for the 90/270 transforms. (4) Drag positions are committed on **release**, not per frame — a drag emits a move per frame and each one rebuilds the working array and every delegate binding; the rectangle follows the snapped drop point through its own `x`/`y` binding (`dragging ? dropX : mon.x`), so a drag never breaks the binding — and edges **snap** to neighbours' (abutting and flush) within a constant on-screen distance converted back into layout pixels. (5) On save the layout is **normalised** so its top-left is 0,0; the arrangement is identical either way, and it keeps the written file looking like one a human would write. (6) The dirty flag is a **JSON compare** against what was loaded, not a flag each control sets — the latter drifts the first time a control forgets. (7) Switching layout re-points a symlink, so an unsaved canvas would be silently abandoned; picking another layout while dirty refuses and says so, and picking the active one re-reads it (the revert gesture). (8) **Identify** (button, `i`, or `qs ipc call monitors identify` — works with the window closed) paints each head's output name on it for 3s via a click-through (`mask: Region {}`) unanchored layer surface, which layer-shell centres. The canvas prefixes connected heads with their `Config.displays` number (outputs left to right, shared with `Super+S 1–3`) — deliberately **not** the layout array index reach uses for `.monitor` rules, which is file order and means nothing on screen. (9) `property string baseline` is not available: `baseline` is FINAL on `Item`, and using it fails the whole shell load with *Cannot override FINAL property*.
