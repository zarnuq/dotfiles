# ClipboardPicker

`ClipboardPicker.qml` — `Picker`-based clipboard history (`Super+V` / `qs ipc call clipboard toggle`), replacing the floating kitty that ran `clipfzf` (**that script is deleted**; it is named below only to explain what the QML does differently). Rows come from one `cliphist list` per **open** — never polled, because a closed picker should cost nothing — and typing filters them by substring. Enter copies (`cliphist decode <id> | wl-copy`), `Ctrl+D` deletes the entry and re-lists, `Ctrl+E` opens a text entry in `$EDITOR` (via `zsh -c`, since qs itself inherits Gentoo's `EDITOR=/bin/nano` and only `.zshenv` sets nvim) on a temp file and copies it back if saved changed (images skipped); `Ctrl+F` toggles the box to fill the output with only the preview (the query row keeps focus, so arrows / `Ctrl+J`/`K` still walk entries). Non-obvious bits: (1) an image entry is recognised from the **list line** (`[[ binary data 40 KiB png 1362x367 ]]`), so nothing is decoded to find out what an entry is; clipfzf decodes each highlighted row and asks `file` for its mime type, because fzf hands it no other hook. (2) The preview decodes lazily behind a 60ms debounce (holding `j` must not spawn a decode per row it passes) and memoizes per id — text through `head -c 4000` into a string, an image into `$XDG_CACHE_HOME/quickshell/clip/<id>.img` because an `Image` needs a file. That was the hard half in the terminal: clipfzf can only draw one by shelling `kitten icat` in unicode-placeholder mode, the one mode that survives fzf's redraws, and only because it always runs inside kitty. (3) The preview `Image` is `sourceSize`-capped to the pane and `cache: false` — capped because **under `QT_QUICK_BACKEND=software` every pixel is decoded and scaled on the CPU**, so a full-resolution screenshot would otherwise be a few hundred MB of pixmap for a 600px pane; uncached because a `cliphist wipe` restarts ids at 1, so a path can come back around holding different bytes (the memo is cleared per open and the decoded files are purged once at startup for the same reason). (4) `wl-copy` forks a daemon to serve the selection, so it has to outlive the call — `Quickshell.execDetached` is that. clipfzf's `>/dev/null 2>&1` on the copy exists only because that daemon inherited kitty's pty and kept the window open; there is no pty here. (5) **Timestamps are ours, not cliphist's** (it stores none): `Clipboard.qml`'s watchers append `<id> <epoch>` to `~/.local/state/quickshell/clip-times` after each store, only when the top id changed (cliphist exits 0 without storing whitespace or `CLIPBOARD_STATE=sensitive` input), and the lister `cat`s it after `cliphist list` — tab-less lines are the log, newest per id wins. Entries copied before the log existed show no time.
