# Commands

`launcher/Commands.qml` — the catalogue behind the launcher's **`>` mode**: the seven surfaces the shell can raise (network, clipboard, audio, displays, wallpaper picker, music, settings) and the five actions with no surface of their own (lock, random wallpaper, annotate clipboard, flash cursor, play/pause). It answers "what can this thing open?" without knowing a keybind, and its rows are also merged into the launcher's plain list (sorted in with the apps; `Launcher.isCmd()` tells the two apart per row), and `>` narrows to menus only, rather than a seventh picker — which is also why it needed no `config.zon` edit, and an unknown key there drops reach to compiled-in defaults with **no binds at all**. Non-obvious bits: (1) **it is a catalogue, not a listing.** `qs ipc show` already enumerates every target and parsing it would stay in sync for free — but it yields `wallpaperpicker / toggle`, not "Wallpaper picker / thumbnail grid", and on a palette the label and the gloss *are* the content. (2) **The keybind on each row is read out of `config.zon`, not written down again.** A label copied into the QML would outlive the bind it names, and a palette advertising the wrong key is worse than one advertising none — so binds are **matched by command**: every row dispatches `qs ipc call <target> <fn>`, which is the exact string config.zon spawns, making the command the join key and a rebind something the list picks up on its own. A flat line scan, not a ZON parse, tracking only the brace depth of the enclosing `.chord` (so `Super+R  n` comes out whole); `.cursor.shake`'s `.command` has no `.key`, which is what renders as "shake". Matching is **exact command first, then any bind on the same target** — the palette says `<target> open` where a bind says `<target> toggle`, but `media` carries three binds, and a loose match taken first labels Play / pause with whichever of prev/next the map happens to yield. (3) Rows dispatch **`open`, never `toggle`** (see the IPC gotcha above), and the launcher **hides before it dispatches** — it is a full-screen overlay on every output, so the surface being summoned has to come up over an empty screen rather than under this one. (4) `run()` goes back in through the front door with the same `qs ipc call` the keybinds use rather than reaching for the component: most of these surfaces are `LazyLoader`-built components, not singletons, so there is no name to reach for, and one path means the palette cannot drift from what the key does.
