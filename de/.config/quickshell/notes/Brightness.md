# Brightness

`Brightness.qml` / `Sys.qml` / `CpuGraph.qml` — `Brightness` is two sliders, brightness over night-light temperature, both bound to `Reach.brightness`/`Reach.temperature` from the socket (no poll). The socket is write-only, so a drag **release** writes one file in `~/.config/reach` — `brightness.zon` (`.gamma.brightness`) or `nightlight.zon` (`.gamma.temperature`) — via tmp+`mv`, then `pkill -HUP -x reach`; reach merges every top-level `*.zon` there (config.zon first, then by name). `.gamma.brightness` is applied only when a reload *changes* it, so the keys keep stepping from there; dragging back to exactly the value the file already holds therefore does nothing. Both files are gitignored per-machine state, and need a reach with directory merging — an older one ignores them. Then CPU/RAM (native `/proc` reads on a 2s Timer), CPU temp from the CPU's hwmon node (`coretemp`/`k10temp`, found once at startup, then a `FileView` read on the same Timer — thermal zones mixed in acpitz/iwlwifi), GPU from one long-running `nvidia-smi -lms 2000`, disk from a `df` `Poll` every 60s; `/proc/net/dev` + `ip -j addr` for net. Two things are gated on a one-shot probe rather than rediscovered per tick: `Sys`'s GPU read on `/proc/driver/nvidia/version` (on the laptop the 2s tick forked an `nvidia-smi` that can only fail, ~43k times a day) and `Power`'s timer on Config's BAT0 probe (the desktop reloaded two files that don't exist every 10s).
