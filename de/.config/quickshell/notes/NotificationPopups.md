# NotificationPopups

`NotificationPopups.qml` — uses `Quickshell.Services.Notifications` (FreeDesktop D-Bus server). **It draws everything the server claims on the bus**, which is not decoration: `NotificationService` sets `actionsSupported`/`imageSupported`/`bodyMarkupSupported`, so apps send buttons, art and markup, and for a while none of the three was rendered — the buttons were unreachable, the art was dropped, and the markup printed as literal `<b>` tags. Three non-obvious bits: (1) the spec splits actions in two — the one keyed **`default`** gets no button and is what activating the body means, so the card's MouseArea invokes it and the rest become buttons; a `resident` notification stays up after an action is invoked, everything else is dismissed by answering it. (2) That card-wide MouseArea is declared **before** the content, because z-order follows declaration order and it would otherwise swallow the buttons' own clicks. (3) The body is `Text.StyledText` — exactly the spec's `<b> <i> <u> <a> <img>` subset, where `RichText` is a whole HTML engine for no gain under the software backend — and the image is `sourceSize`-capped at its drawn 48px for the reason `ClipboardPicker` caps its preview: every pixel is decoded and scaled on the CPU, and `image` is whatever path the app handed over. The history menu deliberately gets none of this: an action expires with its notification. `de/.local/share/dbus-1/services/fr.emersion.mako.service` is a stub (`Exec=/bin/true`) that shadows the system mako activation file — prevents D-Bus from relaunching mako when qs restarts and momentarily drops the `org.freedesktop.Notifications` bus name. **Scrolling:** the stack is capped at half the screen and scrolls a whole card per wheel notch (touchpads need `touchpadStep` of travel), sliding the cards and the visible height together, then resting on whole cards only, with a `↑ n ↓ n` counter under it. Wheel input goes through the cards' own MouseAreas, because a MouseArea takes every wheel event over it (a WheelHandler behind the cards saw none). While anything is up, the surface keeps full height with an input `mask`, so the slide animates items rather than resizing a layer surface every frame.
