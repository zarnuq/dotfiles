# Shared pieces: reach for these before writing your own

**Shared pieces** (what a new widget should reach for before writing its own):
- `Config.qml` — besides the feature catalogue: `Config.scale` / `Config.s(n)` (the one 0.85-on-laptop factor; `Widget` forwards `s()` so cards call it unqualified) and `Config.screen(name)` (the output or null — the "which monitor" loop used to be open-coded in four places).
- `Theme.qml` — the palette (live from `theme-set`'s `~/.local/state/theme/palette.json`; each hex in the file is only the Mocha fallback — see `de/.config/theme/CLAUDE.md`) plus `rowSelectBg`/`rowSelectFg`, the picker's selected-row colours that four files had spelled out as `#11111b`/`#bac2de`; `alpha(c, a)` for a palette colour as a wash (instead of `Qt.rgba(Theme.x.r, Theme.x.g, Theme.x.b, a)`); and `currentWash(selected)`, the current-device / playing-song mauve that `PickerRow` and the music player's rows share.
- `Widget.qml` — the card chrome (pin to the main screen, flat border, padding, Bottom layer). `Txt.qml`/`Field.qml`, `HeaderBtn.qml`, `Graph.qml`, `CardHeader.qml` are the small shared card visuals. `Gauge.qml` (flat track + fill) sits at the **root**, not in `cards/`: the Battery, Brightness and Mpd cards use it, and so do the OSD's level bar and the audio mixer's volume track.
- `Poll.qml` — Timer+Process+StdioCollector in one. `onData` gives raw stdout; **`onJsonData` gives parsed JSON or null**, which is what the four JSON-producing pollers use instead of each writing the same try/catch.
- `Picker.qml` — full-screen overlay pickers: IPC toggle, focused-monitor latching, `hoverMoved`, scale/`s()`, and the shared `rows`/`selected`/`move()`/`firstSelectable()` list navigation that steps over `kind: "header"` entries. `move()` walks **`count`** (default `rows.length`), so the pickers that drive their own results array — Launcher, ClipboardPicker, Processes, WallpaperPicker — point `count` at it and share the one implementation instead of each clamping by hand; a step of more than one row (the wallpaper grid's `j`/`k`) lands on the end of the list rather than refusing, since the last grid row is usually short.
- `PickerRow.qml` — the shared menu row for Settings, Audio, Network, Bluetooth, Drives, Notifications, Processes and the clipboard picker: the chrome (section labels, selection, current-device wash/accent, guarded hover) **and the row's cells** — `icon`, `label`, an optional slot, and a right-aligned `trailing`. Pass the picker and model entry/index (row heights come from the picker), set the cells and handle `activated` (selection has already been updated). The four callers each wrote that `Row` of `Txt`s out by hand and each **computed the label's width by subtracting every other cell and spacing from the parent's** — four copies of a sum that has to be corrected whenever a cell is added or resized; here the label just fills what the others leave, and the sizes/colours that actually differ per menu are properties with defaults. A control goes in the slot as a child of the row (only the audio mixer has one, its volume track) with `slotWidth` reserving the space; children still sit above the row's MouseArea, so the slider keeps its own drag handling.
- `PickerList.qml` — the body of a rows-driven picker: takes focus, offers every key to `Picker.navKey` before its own (`extraKey`), lays `picker.rows` into a Column with the caller's `rowDelegate`, and anchors the bottom bar so a growing list can never push it out of the box. The bar is either `hint` + `status` (keys dim, an action's progress/error in peach over them — Bluetooth, Drives, Notifications) or the caller's own children (Network's warning line and password field). Settings, Audio and Network opened with the same fifteen lines of that, each padding the box slightly differently; `resetting()` is what `Picker`'s `reset()` call becomes.
- `PickerSearch.qml` / `PickerResults.qml` / `PickerFooter.qml` — the query row (field, placeholder, Esc/arrows/Ctrl+J/K; Return is `submitted`, the rest `extraKey`), the selection-following ListView with its empty-state line, and the bottom footer bar (divider, count/status, keyboard hints) shared by ClipboardPicker and Processes. `PickerHover.qml` — the hover-guarded select/click MouseArea used by PickerRow, launcher rows and wallpaper tiles.
- `Field.qml` — `TextInput` with the shell's font, colour and vertical centring baked in, as `Txt` is for `Text`; every input field in the shell (picker query, Network password, lock screen, "save as", the three in the music player) is one.
- `NetworkData.js` — pure snapshot parsing, menu data and decisions for `Network.qml`. The QML owns polling, state and running processes; the helper owns nmcli escaping, VPN grouping, always-on warnings, every row's display fields (`buildRows` stamps `active`/`label`/`icon`/`trailing`), the ~/VPNs mirror's next step (`syncStep`) and the import command (`importCommand`, with the never-default/wireguard reasoning). `vpnRows()` **stamps `label` and `alwaysOn` onto each row** instead of leaving them to be re-derived by name at paint time: both are decided once, when the row is built, and a delegate that asks later has to be handed the whole list to do it. That also closed a latent collision — `warning()` used to match the always-on name across *every* row, and `buildRows` gives an eth row its connection's name, so a wired connection called `wireguard` would have counted as the homelab tunnel being up.
- `BarStatusData.qml` / `BarStatus.qml` / `BarTray.qml` — the bar's shared status sources, per-output status layout and per-output tray/menu respectively. `Bar.qml` creates one status data object for all outputs and owns their surfaces, workspace cells and titles. `BarTray` finds its bar through `QsWindow.window` rather than having it passed down.
- `NotificationService.qml` — the singleton that actually owns `org.freedesktop.Notifications` (replacing mako), plus the rolling 20-entry history and the DND flag. `NotificationPopups` renders `live`, the `Notifications` menu renders `history` — two widgets, one server. History is recorded even under DND (mako logged `invisible=1` notifications too).
- `Sys.qml` — CPU/RAM/disk/GPU, read **only by the `CpuGraph` card**. A singleton is built on first reference, so a machine with that card off never runs its 2s timer, its long-running nvidia-smi or its 60s df.
- `Power.qml` — the battery and mains supply (`present`/`level`/`status`/`charging`/`onAc`), read by the bar's battery block; it also owns the low-charge notification. One 10s read of BAT0 + `AC/online` serves both, which used to poll separately at 30s and 10s. It was split out of `Sys` because the bar is on everywhere: reading the battery through `Sys` built the whole metrics singleton with it — an `nvidia-smi`, a `df` and a thermal `cat` forked every 2s on a machine whose CPU card was switched off.
- `Volume.qml` — the default sink/source and their volume/muted/name, with the one `PwObjectTracker` that keeps them bound. The bar, `Mpd.qml` and `Osd.qml` each carried a copy of that block; `Audio.qml` still walks Pipewire's nodes itself, since the mixer is about the whole graph rather than the defaults — but it takes "which one is the default" (`Volume.sink`/`source`) and a node's display name (`Volume.nameOf()`) from here. It also backs the `volume` IPC target (declared in `shell.qml`, unflagged so the volume keys survive any switch): `up`/`down`/`micUp`/`micDown` step 5% off the last level asked for (fixed steps because `-5` as an argument parses as a CLI flag), `micMute`, and `flip`, which picks the next `effect_input.eq_*` sink and hands it to `useSink()` — the one `flip.sh set` call, shared with `Audio.qml` (card profile + stream migration are pactl-only).
