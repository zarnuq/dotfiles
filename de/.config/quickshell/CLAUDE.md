# Quickshell (`de/.config/quickshell/`)

Loaded when working in this directory. The how-to — constraints, conventions, templates, and how to verify a change — is the **`quickshell` skill** (`.claude/skills/quickshell/`); this file is the per-component *why*. The music player has its own `music/CLAUDE.md`.

**Config:** `de/.config/quickshell/` — QML components + `scripts/` (data providers). Entry point: `shell.qml` (`ShellRoot`), where each feature is one `LazyLoader { active: Config.on("<key>"); <Component>{} }` line — a feature toggled off is **never built** (zero RAM, no daemon), and toggling one at runtime builds or tears it down live, no restart. `active:` is synchronous on purpose (an all-`activeAsync` shell would never load — async loading needs an existing window first). Written in QML/Qt Quick; no separate daemon/open split — `qs` runs in the foreground and runsv supervises it directly.

**Which features are on is per-machine state, not config.** `Config.qml` holds a **catalogue** (`features`: one `{key, group, label}` entry per feature, in menu order) and nothing else; the on/off values live in `~/.local/state/quickshell/features.json`, which is **outside the repo** — not stowed, not committed — so one config serves the desktop and the laptop and each keeps its own set. **Only the OFF switches are stored**: anything absent is on, a missing file means the whole shell, and deleting the file restores everything. Edit it through the settings menu (`Super+Shift+Escape` / `qs ipc call settings toggle`), not by hand — hand-edits only land on the next start or QML reload. Adding a feature is one catalogue entry plus one `shell.qml` line; the menu is generated from the catalogue, so there is no second list to keep in sync.

**Service:** `~/.local/sv/quickshell/run` — waits for dbus+wayland sockets, sets `QT_QPA_PLATFORM=wayland`, `exec qs`. It also sets `QT_QUICK_BACKEND=software` (see **Rendering** below). Unlike eww, no monitor/scale detection in the shell script — that logic lives in `Config.qml` (`DP-2` present → scale 1.0, else 0.85).

**Components (shell.qml, gated by Config flags):** `WallpaperView` (per-screen wallpaper, replaces awww), `WallpaperPicker` (thumbnail grid, `Super+Shift+b`), `NotificationPopups` (toasts, replaces mako popups), `Session` (idle+lock screen, session actions on it; replaces swaylock+swayidle), `Clipboard` (cliphist text+image watchers, replaces the runit cliphist service), `ClipboardPicker` (history picker, `Super+V`, replaces clipfzf), `Clock`, `CpuGraph`, `NetGraph`, `Mpd`, `Weather`, `Notifications` (history panel + DND, top-right, height follows its content), `Calendar`, `Brightness`, `Battery` (laptop low-charge warning), `Osd` (transient volume/mic/brightness/sink indicator), `Spotlight` (shake-to-find cursor), `Launcher` (drun app launcher, replaces rofi), `Network` (Wi-Fi + VPN menu, replaces nmtui — and the VPN half replaced the old bottom-left `Vpn` card; there is deliberately no separate VPN menu, since this one already lists the tunnels), `Bar` (the status bar, replaces reach's baked-in one), `Audio` (sink/source + per-app mixer, replaces pulsemixer), `Music` (MPD client in a tiled **window** rather than an overlay — see its own section), `Monitors` (display configurator in a window — presets, drag-to-arrange, mode/scale/rotation; `Super+R` `m`), `Screenshot` (no surface — the `capture` IPC target the `Super+S` chord calls: `region`, `display <n>` (1-based, left to right; the chord binds 1–3), `output <name>`, `annotate`; turning the flag off takes the chord with it. Every capture goes to the clipboard; `annotate` opens the clipboard image in satty, whose save is the only writer to `~/Pictures`), `Settings` (feature switchboard — the one component with no flag, since disabling it would leave no way back). The `tray` flag has no component of its own: the system tray is a section of `Bar.qml`.

**Layout on disk.** The config root holds the standalone surfaces (pickers, launcher, lock, OSD, wallpaper, notifications server) and the shared singletons. Six subdirectories group the closed clusters — a folder is only made where nothing outside it references the contents:
- **`bar/`** — the status bar: `Bar.qml` and the pieces only it uses — `BarStatus`/`BarStatusData` (per-output layout and the shared status sources), `BarTray`, and `TrayMenu` (reached only through `BarTray`).
- **`cards/`** — the nine ambient desktop cards (`Clock`, `Brightness`, `Calendar`, `Weather`, `Mpd`, `NetGraph`, `CpuGraph`, `Notifications`, `Battery`) and the pieces used only by them: `Widget.qml` (the card chrome), `CardHeader.qml` (icon/label/trailing title row; the icon is optional and trailing items sit in a spaced row), `ListCard.qml` (the flat surface0 entry both the Calendar agenda and the Notifications history draw, with an optional accent strip), `Graph.qml` (fills its parent; overlaid), `HeaderBtn.qml` (also Mpd's transport buttons, via `centered`). `Gauge.qml` is at the root — see **Shared pieces**. `Poll.qml` stays at the root because `Network` and `BarStatusData` use it too. **No `qmldir`** — none of these is a singleton, so the implicit directory import is enough, and adding one would create the must-list-every-file trap that `music/` has.
- **`music/`** — the music player (see its own section). It *does* need a `qmldir`, for its two singletons (`MpdClient`, `Ui`).
- **`launcher/`** — `Launcher.qml` plus `FileIndex.qml` and `FileSearch.js` (the `/` file mode) and `Commands.qml` (the `>` menu mode), none of which anything else uses. `qmldir` for the two singletons.
- **`wallpaper/`** — `Wallpaper.qml` (singleton), `WallpaperView.qml`, `WallpaperPicker.qml`. `qmldir` for the singleton.
- **`monitors/`** — the display configurator: `Monitors.qml` (the `FloatingWindow` + IPC), `MonitorsView.qml` (state, the layout bar, the `monitors.py` calls — two one-shot `Poll`s with `running: false`), `MonitorCanvas.qml` (drag-to-arrange), `MonitorInspector.qml` (mode/scale/rotation steppers) and `MonitorButton.qml`. **No `qmldir`** — no singletons, so the implicit directory import is enough. It owns the whole notion of named layouts; reach only ever sees one file. Non-obvious bits: (1) it is a **window**, like the music player, because a full-screen picker overlay swallows every click while mapped and this is a surface you sit in and resize; reach tiles it by the shared `org.quickshell` app_id, so a rule must narrow by the title `Displays`. (2) The canvas draws **layout entries and live outputs together**, distinguishing *not connected* (in the layout, nothing plugged in — peach) from *not in layout* (plugged in, unlisted — dimmed): that is what lets the desktop's arrangement be edited from the laptop, which is the whole point of separate files. An unlisted head is parked to the **right** of the arrangement rather than at 0,0, where it would sit on top of the first monitor. (3) A rotated head's `w`/`h` are its MODE, so every size question goes through `effW`/`effH` (and bounding boxes through `extent()`, which the canvas fit, the save normalisation and the unlisted-head parking share), which swap them for the 90/270 transforms. (4) Drag positions are committed on **release**, not per frame — a drag emits a move per frame and each one rebuilds the working array and every delegate binding; the rectangle follows the snapped drop point through its own `x`/`y` binding (`dragging ? dropX : mon.x`), so a drag never breaks the binding — and edges **snap** to neighbours' (abutting and flush) within a constant on-screen distance converted back into layout pixels. (5) On save the layout is **normalised** so its top-left is 0,0; the arrangement is identical either way, and it keeps the written file looking like one a human would write. (6) The dirty flag is a **JSON compare** against what was loaded, not a flag each control sets — the latter drifts the first time a control forgets. (7) Switching layout re-points a symlink, so an unsaved canvas would be silently abandoned; picking another layout while dirty refuses and says so, and picking the active one re-reads it (the revert gesture). (8) **Identify** (button, `i`, or `qs ipc call monitors identify` — works with the window closed) paints each head's output name on it for 3s via a click-through (`mask: Region {}`) unanchored layer surface, which layer-shell centres. The canvas prefixes connected heads with their `Config.displays` number (outputs left to right, shared with `Super+S 1–3`) — deliberately **not** the layout array index reach uses for `.monitor` rules, which is file order and means nothing on screen. (9) `property string baseline` is not available: `baseline` is FINAL on `Item`, and using it fails the whole shell load with *Cannot override FINAL property*.

Each is reached with a directory import in `shell.qml` (`import "bar"`, `import "cards"`, `import "music"`), and every file inside carries `import ".."` for the root-level `Theme`/`Config`/`Txt`/`Poll` and the data singletons (`Reach`, `Sys`, `Power`, `Volume`, `NotificationService`). Only `music/` has a `qmldir`, and only because of its singletons — `bar/` and `cards/` contain none, so the implicit directory import resolves them and they avoid the must-list-every-file trap.

**QML conventions.** Every file carries `pragma ComponentBehavior: Bound` (after `pragma Singleton` in a singleton) and its root object is `id: root`. A delegate declares `required property var modelData` / `required property int index`, gets its own `id`, and its children read `thatId.modelData` — never the bare context name. A picker's `box: Component` defined in one file and loaded by `Picker.qml`'s Loader keeps its outer ids under `Bound` (checked). Functions that return nothing are annotated `: void`; parameters are deliberately left **untyped**, because a QML annotation coerces the argument (`int` truncates a real, `string` turns `null` into `"null"`) and 281 call graphs were not audited for that. `tests/lint.sh` is the check (see **Tests** in the root `CLAUDE.md`).

**What stays at the root, and why.** `Theme`/`Config`/`Txt`/`Poll` are used by everything, and `Gauge` by the cards, the OSD and the mixer; `Picker`/`PickerList`/`PickerRow`/`PickerHover`/`PickerSearch`/`PickerResults` are the menu chrome behind seven surfaces; `Reach`/`Sys`/`Power`/`Volume`/`NotificationService` are shared state singletons; and `Audio`, `Network`, `Session`, `Settings`, `Osd`, `Spotlight`, `NotificationPopups` and the clipboard pair are standalone surfaces with no cluster to join.

**`Reach.qml` belongs to no folder on purpose.** reach publishes one JSON snapshot carrying both window-manager state and gamma, so `bar/Bar.qml` reads `desktops`/`forScreen()` from it while `cards/Brightness.qml` and `Osd.qml` read `brightness`. Filing it under `bar/` would make the gamma readers import the bar.

**Shared pieces** (what a new widget should reach for before writing its own):
- `Config.qml` — besides the feature catalogue: `Config.scale` / `Config.s(n)` (the one 0.85-on-laptop factor; `Widget` forwards `s()` so cards call it unqualified) and `Config.screen(name)` (the output or null — the "which monitor" loop used to be open-coded in four places).
- `Theme.qml` — the palette plus `rowSelectBg`/`rowSelectFg`, the picker's selected-row colours that four files had spelled out as `#11111b`/`#bac2de`; `alpha(c, a)` for a palette colour as a wash (instead of `Qt.rgba(Theme.x.r, Theme.x.g, Theme.x.b, a)`); and `currentWash(selected)`, the current-device / playing-song mauve that `PickerRow` and the music player's rows share.
- `Widget.qml` — the card chrome (pin to the main screen, flat border, padding, Bottom layer). `Txt.qml`/`Field.qml`, `HeaderBtn.qml`, `Graph.qml`, `CardHeader.qml` are the small shared card visuals. `Gauge.qml` (flat track + fill) sits at the **root**, not in `cards/`: the Battery, Brightness and Mpd cards use it, and so do the OSD's level bar and the audio mixer's volume track.
- `Poll.qml` — Timer+Process+StdioCollector in one. `onData` gives raw stdout; **`onJsonData` gives parsed JSON or null**, which is what the four JSON-producing pollers use instead of each writing the same try/catch.
- `Picker.qml` — full-screen overlay pickers: IPC toggle, focused-monitor latching, `hoverMoved`, scale/`s()`, and the shared `rows`/`selected`/`move()`/`firstSelectable()` list navigation that steps over `kind: "header"` entries. `move()` walks **`count`** (default `rows.length`), so the three pickers that drive their own results array — Launcher, ClipboardPicker, WallpaperPicker — point `count` at it and share the one implementation instead of each clamping by hand; a step of more than one row (the wallpaper grid's `j`/`k`) lands on the end of the list rather than refusing, since the last grid row is usually short.
- `PickerRow.qml` — the shared menu row for Settings, Audio, Network and the clipboard picker: the chrome (section labels, selection, current-device wash/accent, guarded hover) **and the row's cells** — `icon`, `label`, an optional slot, and a right-aligned `trailing`. Pass the picker, model entry/index and row heights, set the cells and handle `activated` (selection has already been updated). The four callers each wrote that `Row` of `Txt`s out by hand and each **computed the label's width by subtracting every other cell and spacing from the parent's** — four copies of a sum that has to be corrected whenever a cell is added or resized; here the label just fills what the others leave, and the sizes/colours that actually differ per menu are properties with defaults. A control goes in the slot as a child of the row (only the audio mixer has one, its volume track) with `slotWidth` reserving the space; children still sit above the row's MouseArea, so the slider keeps its own drag handling.
- `PickerList.qml` — the body of a rows-driven picker: takes focus, offers every key to `Picker.navKey` before its own (`extraKey`), lays `picker.rows` into a Column with the caller's `rowDelegate`, and anchors the bottom bar (its children) so a growing list can never push it out of the box. Settings, Audio and Network opened with the same fifteen lines of that, each padding the box slightly differently; `resetting()` is what `Picker`'s `reset()` call becomes.
- `PickerSearch.qml` / `PickerResults.qml` — the query row (field, placeholder, Esc/arrows/Ctrl+J/K; Return is `submitted`, the rest `extraKey`) and the selection-following ListView with its empty-state line, shared by Launcher and ClipboardPicker. `PickerHover.qml` — the hover-guarded select/click MouseArea used by PickerRow, launcher rows and wallpaper tiles. PickerRow's row heights default to its picker's.
- `Field.qml` — `TextInput` with the shell's font, colour and vertical centring baked in, as `Txt` is for `Text`; every input field in the shell (picker query, Network password, lock screen, "save as", the three in the music player) is one.
- `NetworkData.js` — pure snapshot parsing, menu data and decisions for `Network.qml`. The QML owns polling, state and running processes; the helper owns nmcli escaping, AP deduplication, VPN grouping, always-on warnings, every row's display fields (`buildRows` stamps `active`/`label`/`icon`/`trailing`), the ~/VPNs mirror's next step (`syncStep`) and the import command (`importCommand`, with the never-default/wireguard reasoning). `vpnRows()` **stamps `label` and `alwaysOn` onto each row** instead of leaving them to be re-derived by name at paint time: both are decided once, when the row is built, and a delegate that asks later has to be handed the whole list to do it. That also closed a latent collision — `warning()` used to match the always-on name across *every* row, and `buildRows` gives an eth row its connection's name, so a wired connection called `wireguard` would have counted as the homelab tunnel being up.
- `BarStatusData.qml` / `BarStatus.qml` / `BarTray.qml` — the bar's shared status sources, per-output status layout and per-output tray/menu respectively. `Bar.qml` creates one status data object for all outputs and owns their surfaces, workspace cells and titles. `BarTray` finds its bar through `QsWindow.window` rather than having it passed down.
- `NotificationService.qml` — the singleton that actually owns `org.freedesktop.Notifications` (replacing mako), plus the rolling 20-entry history and the DND flag. `NotificationPopups` renders `live`, the `Notifications` panel renders `history` — two widgets, one server. History is recorded even under DND (mako logged `invisible=1` notifications too).
- `Sys.qml` — CPU/RAM/disk/GPU, read **only by the `CpuGraph` card**. A singleton is built on first reference, so a machine with that card off never runs its 2s timer or its three polls.
- `Power.qml` — the battery and mains supply (`present`/`level`/`status`/`charging`/`onAc`), read by the bar's battery block and the `Battery` card. One 10s read of BAT0 + `AC/online` serves both, which used to poll separately at 30s and 10s. It was split out of `Sys` because the bar is on everywhere: reading the battery through `Sys` built the whole metrics singleton with it — an `nvidia-smi`, a `df` and a thermal `cat` forked every 2s on a machine whose CPU card was switched off.
- `Volume.qml` — the default sink/source and their volume/muted/name, with the one `PwObjectTracker` that keeps them bound. The bar, `Mpd.qml` and `Osd.qml` each carried a copy of that block; `Audio.qml` still walks Pipewire's nodes itself, since the mixer is about the whole graph rather than the defaults — but it takes "which one is the default" (`Volume.sink`/`source`) and a node's display name (`Volume.nameOf()`) from here.

**Rendering:** `QT_QUICK_BACKEND=software` in the service script (which also sets `QT_WAYLAND_DISABLE_WINDOWDECORATION=1`, for the music window's xdg-shell toplevel — Qt would otherwise draw a grey titlebar on it). The shell is flat rectangles, text and one wallpaper blit, but the GL scenegraph gives **every visible window** its own render thread and Mesa context, and there are ~15 of them (a wallpaper and a bar per output, plus one per ambient card) — 589 MB RSS / 135 threads on the AMD laptop, against 260 MB / 22 with QPainter. The cost is that GPU-only QML types silently draw nothing: no `ShaderEffect`, `layer.effect` or `MultiEffect` in here (`TrayMenu.qml` tints its icons with `QtQuick.Controls.impl`'s `ColorImage`, which recolours on the CPU, for exactly this reason). Drop the line if a wallpaper crossfade ever stutters on the 3×3440x1440 desktop.

**Notable wiring:**
- `Bar.qml` / `Reach.qml` — the status bar, one per output, replacing the one reach drew itself; same layout (`[desktops] [title … app_id] [status]`), same colours, same hide-vacant/focused-monitor-highlight rules (reach's occupied-corner box was dropped — the cell being drawn at all already says it), so the switch is invisible. `Reach.qml` is the singleton holding window-manager state from reach's socket (see **State socket** in `de/.config/reach/CLAUDE.md`); `forScreen(name)` is how each bar finds its own output. Non-obvious bits: (1) it is an ordinary **layer surface**, so its `exclusiveZone` reserves the strip and the compositor pushes windows *and* the other quickshell cards below it — reach's bar was a river shell surface and had to subtract itself from the layout by hand (`Output.usableArea`). (2) The socket retry is driven by `running: !sock.connected`, **not** by `onConnectionStateChanged`: a connect that *fails* never entered the connected state, so there is no state change to hear and the first attempt would be the only one — the bar would stay blank for the whole session. 5s, only to keep the log quiet (each failure logs); the normal path never retries, since reach's autostart starts runsvdir and is listening before quickshell exists. (3) Hidden (`visible: false`, which releases the exclusive zone with it) when a window is fullscreen on that output, matching reach. (4) The highlight is `Reach.selected(name)`, not `wm.focused` — see **Selected output follows the pointer** in `de/.config/reach/CLAUDE.md`; the socket alone cannot move while the mouse crosses onto an empty monitor. (5) The status side is native — volume/mic from the `Volume` singleton, battery from `Sys`, clock in QML, one `sh -c` for the default-route IP — which is what retired the six block scripts and the `kill -35`/`-36` refresh binds.
- `Spotlight.qml` — dims every output and leaves a clear, feathered circle around the pointer (PowerToys' Find My Mouse), fired by reach's shake detector. Non-obvious bits: (1) **the overlay must accept input**, because that is the only way any Wayland client can learn the cursor position — the `enter` event carries surface-local coords. So it swallows clicks while mapped, which is why it is transient and dismisses on any key, any click, or ~60px of movement, with a 4s safety timeout. (2) Movement-dismiss is armed only after a 600ms grace period: the gesture that summons it *is* the pointer moving, so without that the shake would dismiss it in the same frame. (3) Under `QT_QUICK_BACKEND=software` there is no `ShaderEffect` to punch a hole with, so the wash is four plain `Rectangle`s around a square gap plus one small `Canvas` filling that square (`destination-out` = `QPainter::CompositionMode_DestinationOut`). The Canvas image is **position-independent**, so it paints once and is only ever moved — nothing repaints a screenful of pixels on the CPU as the pointer travels.
- `Session.qml` — the lock screen *is* the power menu. `Super+P` locks (`qs ipc call lock lock`), `IdleMonitor` locks at 300s, `WlSessionLock` (ext-session-lock) + PAM unlocks — and the surface carries Power off / Reboot / Log out under the password field. Three files collapsed into this one (`Lock.qml`, `PowerMenu.qml`): a menu offering "Lock" and a lock screen offering nothing were two halves of the same thing, and the `power` IPC target is gone with the overlay. Non-obvious bits: (1) the password field **keeps focus permanently** — arrows and Tab arm an action from inside its `Keys.onPressed` rather than moving focus (Down/Right step into the row, Up/Left back out to the field), so a password typed at any moment still lands in the box it was meant for, and typing disarms (a stray Tab can't turn the next Return into a poweroff); nothing fires on one keystroke or one click, it's arm-then-confirm. (2) poweroff/reboot run `doas -n <cmd>` with the **bare** command name, matching this box's `permit nopass :wheel cmd poweroff` rule — `/usr/bin/poweroff` misses it and falls back to a password-requiring rule. They need doas at all because `/usr/bin/poweroff` (the runit-shutdown dispatcher) self-elevates with doas itself, and the old unlocked menu could spawn a floating kitty for that prompt — but the lock surface sits above every window, so the prompt would be invisible and unfocusable there. `-n` fails fast instead of hanging on a prompt no one can reach, and the surface says so rather than doing nothing.
- `Audio.qml` — `Picker`-based mixer: output devices, input devices, and a volume row per playing app (`Super+R` `A` / `qs ipc call audio toggle`; replaced `kitty --class float -e pulsemixer`). Rows are classified by `media.class`, **not** `isSink`/`isStream` — a playback stream reports `isSink` true as well, since it feeds one. App streams are those carrying an `application.name`; that is exactly what excludes the EQ filter-chains' own `effect_output.*` playback streams and the mic loopback, which must never be dragged along when streams migrate. `PwObjectTracker` stays armed on all nodes rather than being gated on `open`, because a node only publishes `.audio` while something holds a binding and the menu has to be right in the frame it opens. Picking a **sink** shells out to `flip.sh set <name>` instead of setting `Pipewire.preferredDefaultAudioSink` — the optical chain needs a card-profile flip first and existing streams need moving by hand, and that logic already lives in the script `Alt+[` uses. Sources just set `preferredDefaultAudioSource`. The current default sink/source carries a mauve wash plus a left accent bar, brightening when selected rather than being covered by the selection band — tinting only its icon was invisible under the cursor. Keys: `j`/`k` select, `h`/`l` volume ±5%, `m` mute, `Return` activate. **The level drawn is the one asked for, not the one read back:** a write reaches `audio.volume` again only after Pipewire applies it and says so, so a slider bound straight to that property trailed the pointer by a round trip. `levelOf()` returns the wanted value for the node being changed until a 200ms settle hands it back to the graph, and the writes are throttled to one per 40ms (leading edge, trailing flush) — a drag emits a mouse move per frame and each one was a graph update. `nudge()` steps off the wanted level for the same reason: held keys were losing increments to the stale echo.
- `Network.qml` — `Picker`-based Wi-Fi + VPN menu (`Super+R` `N` / `qs ipc call network toggle`), replacing the floating kitty running nmtui. **This is also where the VPNs live** — a bottom-left `Vpn` card and then a separate VPN menu both came and went, because this menu already lists every tunnel and a second surface for the same rows is a second thing to keep honest. Non-obvious bits: (1) **every tunnel is an NM profile.** The lab `~/VPNs/*.ovpn` configs used to be run by `scripts/vpn-manager.sh` as a bare root `openvpn --daemon` NM knew nothing about; that needed a doas rule to start one and a *second* doas rule to kill one, scraped the profile's state out of `pgrep`+`/proc/<pid>/cmdline`, and surfaced as an *externally connected* `tun0`. When the kill rule didn't match, `disconnect` failed silently, `connect` stacked a second daemon, two tunnels ran at once on two tun devices — and each rejected `doas` counted as a failed login until the account locked for ten minutes. They are now imported (`nmcli connection import type openvpn file <f>`, which `nmcli general permissions` allows this user) and are ordinary NM connections: one code path, up/down by UUID, state from the snapshot the menu already takes, **no daemon, no script, no doas rule, nothing to scrape**. An `~/VPNs/*.ovpn` NM hasn't been given yet is **imported automatically** while the menu is open (`pendingImports` matches files against NM profiles by the name NM would give them, so an imported file is never handed over twice), which keeps "drop a lab config in `~/VPNs`" as the whole workflow. **The VPN section is a MIRROR of that directory** (plus the always-on tunnels), and it covers both kinds: **`*.ovpn` imports as openvpn, `*.conf` as wireguard** (`nmcli connection import type wireguard`), so a temporary wg config is dropped in the same place as a lab config. A file with no profile is imported, a profile whose file **changed** is deleted and re-imported, and a `type=vpn` profile with no file behind it is **deleted** — either the registry (`~/.local/state/quickshell/vpn-sources.json`) remembers the file it came from and that file is gone, or nothing has ever heard of the profile and no file would produce its name. That second case is what used to leave permanent garbage in the menu: a profile imported before the registry existed, or by hand, is in no registry to age out of. The change check is a **sha256 of the file**, recorded in the registry at import (`sha256sum` rides in the same listing poll). Name matching alone is not enough and this is not theoretical: HTB reissues a config under the same filename pointing at a new server, so `HTB-TCP.ovpn` said `dedivip-4` while the profile NM kept serving still said `dedivip-3` — every connection through the menu timed out while the very same file worked from a terminal, which is the confusing shape this takes. An entry with no stored hash predates the check; `adoptSources` stamps one on the next pass rather than re-importing on a guess. Consequence worth knowing: **an OpenVPN profile you created by other means, for a config that does not live in `~/VPNs`, will be removed** — put its name in `ALWAYS_ON` to exempt it. A WireGuard profile is only ever removed when the registry itself imported it and its file is gone — an **untracked** wireguard profile is left alone however it got there, because it holds a private key that may have no other copy, whereas an openvpn profile can always be rebuilt from its file. For the same reason a wireguard import is a bare `con import` with **no** `con mod` chained on: unprivileged, that drops the key it just stored. A wg tunnel takes its routes from `AllowedIPs`, so if one carries `0.0.0.0/0` and you want it split, that is a one-off `doas nmcli con mod <uuid> ipv4.never-default yes`. Both halves are gated on `filesSeen`, a listing that actually succeeded, so an unreadable `~/VPNs` can never read as "delete everything". **The import also sets `ipv4.never-default`/`ipv6.never-default` on the new profile, in the same command** — HTB pushes `default via <tun gw> metric 50`, which outranks the Wi-Fi default (metric 600), so without it every packet including DNS goes down a tunnel that carries no general internet and the machine drops off the network the instant a lab connects. `never-default` discards only that default; the lab subnets it also pushes (10.10.x, 10.129.x, 10.13.37/38) keep their routes. These are lab configs by definition, so split tunnel is the policy. The UUID comes from the import's own stdout, never a name lookup, and stdout is reprinted so the registry's own UUID match still sees it. The import goes through the same `run()` queue as user actions — two nmcli writes at once, or an import stomping the status line mid-connect, is the only way it could be worse than the manual step — and **three guards** keep it from making duplicate profiles, each answering a different question. (a) `importTried`, cleared on open: stops a file NM refuses from retrying every 5s and owning the status line, while still letting it succeed on the next open once the plugin is there. (b) `importDone`, never cleared: `nm.refresh()` is asynchronous, so for a second or two after an import `conns` still lacks the new profile — close and reopen the menu in that window and the name match says "missing" again. (c) `nmSeen`: **no import before the first nmcli snapshot has landed.** The file listing and the snapshot are independent polls and the listing usually wins, so with `conns` still empty every profile NM already has looks un-imported. That one produced exactly one duplicated profile per cold start — the first file in the list — because the import's own refresh corrected the snapshot before the next file was considered. The openvpn plugin's descriptor is at **`/usr/lib/NetworkManager/VPN/nm-openvpn-service.name`** (not `lib64`). Needs **`net-vpn/networkmanager-openvpn`**; without it `con import` fails with `unknown VPN plugin`. (2) The homelab tunnel — the NM `wireguard` profile, from the root-only `/etc/wireguard` config — is named in one `ALWAYS_ON` list in `NetworkData.js`. **That profile is currently absent** (deleted 2026-09-13; the tunnel moved to the defguard client, which NM doesn't own), so as of now `ALWAYS_ON` matches nothing: no Homelab section, no down-warning. The list, and the routing note below it, describe how it behaves when an NM profile by that name exists (by NM *connection* name, the only name the rows carry); it gets its own section, a red **down** marker, and the warning line. The `~/VPNs/*.ovpn` profiles are HackTheBox/TryHackMe labs and fall into "Labs". **The two overlap in 10/8 and the lab wins by default:** the homelab peer's `allowed-ips=10.0.0.0/8` installs one `10.0.0.0/8 dev wireguard metric 50` route, while HTB's openvpn pushes `10.10.8.0/22 via 10.10.14.1 dev tun0` — which *contains* the homelab's own `10.10.10.0/24`, and longest prefix beats metric, so with a lab up every homelab packet goes down the lab tunnel (`ip route get 10.10.10.1` names the device that actually wins). The profile therefore carries an explicit `ipv4.routes 10.10.10.0/24`, a longer prefix than the lab's /22. The cost is that HTB's legacy 10.10.10.x machines are unreachable while the homelab is up — `nmcli con down wireguard` for those. DNS needs no tunnel: homelab names are public records under `zarz.org`, so the profile's `ipv4.dns` is deliberately `1.1.1.1,1.0.0.1` and `ipv4.dns-priority=-50` is there only to stop eduroam's DHCP resolvers from replacing that list. The route edit is a `doas nmcli con mod <uuid> +ipv4.routes 10.10.10.0/24`: unprivileged `con mod` on a system connection silently destroys the stored private key. **Enter only ever connects, `d` disconnects**, for every row kind: toggling on Return put the always-on tunnel one stray keystroke from being dropped. (3) Nothing elevates — `con up`/`con down`/`device wifi connect` and `con import` are all fine unprivileged (`nmcli general permissions` lists `settings.modify.system` as yes). The menu runs `con mod` in exactly one place, the import above, and only against a profile it created one line earlier: unprivileged `con mod` drops a profile's stored secrets, but a fresh openvpn import has none — the certs are extracted to `~/.local/share/networkmanagement/certificates/nm-openvpn/*.pem` and referenced by PATH, so `vpn.secrets` is empty. Never `con mod` an existing profile (that is what destroys the wireguard private key). (4) NM connections are acted on by **UUID**, never by name (`con up id <name>` is ambiguous — several connections may share a name), and a VPN row whose *device* reads `connected (externally)` is labelled **external**: that is NM describing a `wg-quick` link it merely assumed, backed by a volatile profile in `/run`, not a profile you saved. (5) Joining is `nmcli device wifi connect <ssid>`, **never** by connection name: eduroam's profile is named `eduroam [a8f5604d]`, so name-matching would miss it and create a second profile. NM asks for a key by *failing*, so a secrets error grows a password field in the bottom bar and retries once (the key rides in argv — nmcli takes it no other way). (6) Connections, devices and the radio switch share one tagged `sh -c` (~25ms) because they're one snapshot and separate timers show a torn one — but **the AP list is deliberately not in it**. `nmcli device wifi list` defaults to `--rescan auto`, which **blocks ~3.4s** whenever the scan cache is over 30s old (24ms when fresh), and as the last command in the shared `sh -c` it held the whole snapshot back: an open with a cold cache drew a menu with no Wi-Fi *and* no wired rows, leaving only the rows from the separate `~/VPNs` listing. So it's its own `Poll` with `--rescan no` (cache read, always instant), and the scan request goes out detached on a 15s timer, with the next tick collecting the results. All polls are `running: root.open`, so a closed menu costs nothing. nmcli's terse output escapes `:` as `\:`, so the parser unescapes rather than plain-splitting.
- `FileIndex.qml` — the corpus and ranking behind the launcher's `/` file mode; deliberately **not** a shell-out to `fd | fzf`, because both halves of that pipeline are wrong here. (1) **The corpus.** Anything that follows symlinks (`fzf`'s default walker, `find -L`, `fd -L`) leaves $HOME through `.nix-defexpr/channels` and `.local/state/nix/profiles` into `/nix/store` — $HOME goes from ~46k entries to **3.6M**, nearly all duplicate nix channel trees, and a `fd -L` over it doesn't finish in two minutes. `fd` without `-L` plus the `excludes` list (caches, Steam, the stowed `icons`+`fonts` themes at ~95k files between them) gives ~46k entries in ~0.1s. (2) **The match.** fzf scores a subsequence anywhere in the *whole path*, so "home-manager" matches `.../home-manager/po/tok.po` — the query hit the directory and the file it returned was unrelated. Here a query matches the **basename**; a `/` in the query splits it, and the part before must be a plain **substring of the directory** (subsequence-matching a path is all noise). Literal tiers (exact / prefix / word-start / substring) rank above subsequence-fuzzy, which is span-capped and needs 4+ chars, and a leading `.` is stripped from the basename so `zshrc` finds `.zshrc`. Depth, hidden segments and a `demoted` list (`.local/share`, `site-packages`, `Music`, `Downloads`) are penalties, not exclusions. **Symlink dedupe:** stow gives every config two names (`~/.config/home-manager` is a link to `~/dotfiles/de/.config/home-manager`), and **89 of this tree's 115 symlinks** are that kind of duplicate, so a second `fd --type l ... -x sh -c 'printf "%s\t%s" "$1" "$(readlink -f "$1")"'` pass runs **first** and the main walk drops any link whose target it also indexes (46,332 -> 46,244 entries, build 0.7s -> 0.9s). The **link** is dropped, not the target: fd never descends a symlink, so the link side has no indexed children while the target side has all of them — keeping the target is what makes a parent and its contents agree about where they live. Non-obvious bits: **(a)** the index (lowercased basename/path, precomputed penalties) is built once per enumeration — lowercasing 46k paths per keystroke is the entire cost of a naive filter; **(b)** **incremental narrowing** — candidacy (subsequence) is monotone in the query, so each further character is scored only against the previous survivors: ~50-130ms for the first keystroke of a query, ~1ms after, which is why the launcher debounces 40ms and why backspace (non-monotone) re-scans; **(c)** candidacy is deliberately the *loosest* rule even when the score then rejects the entry — gating the pool on the score would make it non-monotone and silently drop matches as you type; **(d)** a native `indexOf` on the query's first character guards the JS subsequence loop, since nearly all 46k entries are misses and this keeps the cold scan a memchr rather than an interpreter loop; **(e)** hits are packed as `score * 1e6 + index` into one numeric array — 46k `{score, index}` allocations per keystroke was most of the cost; **(f)** the index is built on first entering `/` mode and **released 60s after the launcher closes** (~10 MB of JS strings), which is also what keeps it from going stale, since a rebuild is only ~0.1s of `fd`.
- `launcher/Commands.qml` — the catalogue behind the launcher's **`>` mode**: the seven surfaces the shell can raise (network, clipboard, audio, displays, wallpaper picker, music, settings) and the five actions with no surface of their own (lock, random wallpaper, annotate clipboard, flash cursor, play/pause). It answers "what can this thing open?" without knowing a keybind, and it is a third sigil on the query the launcher already has (`""` apps, `/` files, `>` menus) rather than a seventh picker — which is also why it needed no `config.zon` edit, and an unknown key there drops reach to compiled-in defaults with **no binds at all**. Non-obvious bits: (1) **it is a catalogue, not a listing.** `qs ipc show` already enumerates every target and parsing it would stay in sync for free — but it yields `wallpaperpicker / toggle`, not "Wallpaper picker / thumbnail grid", and on a palette the label and the gloss *are* the content. (2) **The keybind on each row is read out of `config.zon`, not written down again.** A label copied into the QML would outlive the bind it names, and a palette advertising the wrong key is worse than one advertising none — so binds are **matched by command**: every row dispatches `qs ipc call <target> <fn>`, which is the exact string config.zon spawns, making the command the join key and a rebind something the list picks up on its own. A flat line scan, not a ZON parse, tracking only the brace depth of the enclosing `.chord` (so `Super+R  n` comes out whole); `.cursor.shake`'s `.command` has no `.key`, which is what renders as "shake". Matching is **exact command first, then any bind on the same target** — the palette says `<target> open` where a bind says `<target> toggle`, but `media` carries three binds, and a loose match taken first labels Play / pause with whichever of prev/next the map happens to yield. (3) Rows dispatch **`open`, never `toggle`** (see the IPC gotcha above), and the launcher **hides before it dispatches** — it is a full-screen overlay on every output, so the surface being summoned has to come up over an empty screen rather than under this one. (4) `run()` goes back in through the front door with the same `qs ipc call` the keybinds use rather than reaching for the component: most of these surfaces are `LazyLoader`-built components, not singletons, so there is no name to reach for, and one path means the palette cannot drift from what the key does.
- `ClipboardPicker.qml` — `Picker`-based clipboard history (`Super+V` / `qs ipc call clipboard toggle`), replacing the floating kitty that ran `clipfzf` (**that script is deleted**; it is named below only to explain what the QML does differently). Rows come from one `cliphist list` per **open** — never polled, because a closed picker should cost nothing — and typing filters them by substring. Enter copies (`cliphist decode <id> | wl-copy`), `Ctrl+D` deletes the entry and re-lists. Non-obvious bits: (1) an image entry is recognised from the **list line** (`[[ binary data 40 KiB png 1362x367 ]]`), so nothing is decoded to find out what an entry is; clipfzf decodes each highlighted row and asks `file` for its mime type, because fzf hands it no other hook. (2) The preview decodes lazily behind a 60ms debounce (holding `j` must not spawn a decode per row it passes) and memoizes per id — text through `head -c 4000` into a string, an image into `$XDG_CACHE_HOME/quickshell/clip/<id>.img` because an `Image` needs a file. That was the hard half in the terminal: clipfzf can only draw one by shelling `kitten icat` in unicode-placeholder mode, the one mode that survives fzf's redraws, and only because it always runs inside kitty. (3) The preview `Image` is `sourceSize`-capped to the pane and `cache: false` — capped because **under `QT_QUICK_BACKEND=software` every pixel is decoded and scaled on the CPU**, so a full-resolution screenshot would otherwise be a few hundred MB of pixmap for a 600px pane; uncached because a `cliphist wipe` restarts ids at 1, so a path can come back around holding different bytes (the memo is cleared per open and the decoded files are purged once at startup for the same reason). (4) `wl-copy` forks a daemon to serve the selection, so it has to outlive the call — `Quickshell.execDetached` is that. clipfzf's `>/dev/null 2>&1` on the copy exists only because that daemon inherited kitty's pty and kept the window open; there is no pty here.
- `Osd.qml` — transient indicator for volume / mic / brightness / default-sink changes. The gap it filled: the only feedback for `Alt+Up/Down`, `Alt+Left/Right` and `Super+Alt+Left/Right` was the bar, which lives on one monitor — press a key while looking at another and nothing visibly happened; `Alt+[` (flip.sh) was worse, since the only way to learn where audio went was to play something. Non-obvious bits: (1) it draws on **every** output, not the focused one — reach names no focused monitor over IPC and the pointer-containment trick `Picker.qml` uses needs a full-screen surface, which would swallow clicks for as long as it's mapped; each OSD window is only as large as the indicator and only mapped while shown, so it never eats input. (2) **Nothing polls** — volume/mic ride the `Volume` singleton's properties (Pipewire's own signals underneath), brightness is a property change on the `Reach` singleton (reach publishes it on its socket; this is what retired the `gdbus monitor` subprocess), and the sink label falls out of `Volume.sink` changing identity.
- `WallpaperPicker.qml` — `Picker`-based category sidebar + thumbnail grid (`Super+Shift+b` / `qs ipc call wallpaperpicker toggle`). Tiles come from `~/.cache/wallpaper-thumbs`, **never** the originals — decoding a 22MB 7264x4096 PNG per tile is what makes a previewer peg every core (it's why yazi's spun the fans). `~/.local/bin/wallpaper-thumbs` renders them and `--list` emits `category<TAB>source<TAB>thumb`, so the naming rule lives in that script and nowhere else; the picker re-runs it on every open (~35ms warm) so wallpapers added since last time appear. The `;` between render and list is deliberate — a failed render still lists what's there. Source dimensions are memoized per path so revisiting a tile never re-probes.
- `Wallpaper.qml` / `WallpaperView.qml` — singleton; `IpcHandler` target `"wallpaper"` → `random` or `set <path>`; `Super+b` = `qs ipc call wallpaper random`; picks from `~/Pictures/bgs`. **RAM-critical:** the `Image` layers use `cache: true` + a single shared `sourceSize` (`Wallpaper.decodeSize`, the global max output WxH) so **all outputs share ONE decoded buffer** via `QQuickPixmapCache` — do **not** set `cache: false` or per-output `sourceSize` (that's what made every monitor hold its own copy, ~114 MB). The two crossfade layers free their source once faded out, so steady state holds a single buffer. GPU textures are still per-window but live in VRAM (nvidia), not RSS.
- `Clipboard.qml` — `Scope` with a `Variants` over `["text", "image"]` instantiating two self-restarting `Process` watchers (`wl-paste --type text/image --watch cliphist store`); inherits qs's `WAYLAND_DISPLAY` (no socket-wait needed). Replaced the runit `cliphist` group service. The picker half is `ClipboardPicker.qml` now, not `clipfzf`.
- `NotificationPopups.qml` — uses `Quickshell.Services.Notifications` (FreeDesktop D-Bus server). **It draws everything the server claims on the bus**, which is not decoration: `NotificationService` sets `actionsSupported`/`imageSupported`/`bodyMarkupSupported`, so apps send buttons, art and markup, and for a while none of the three was rendered — the buttons were unreachable, the art was dropped, and the markup printed as literal `<b>` tags. Three non-obvious bits: (1) the spec splits actions in two — the one keyed **`default`** gets no button and is what activating the body means, so the card's MouseArea invokes it and the rest become buttons; a `resident` notification stays up after an action is invoked, everything else is dismissed by answering it. (2) That card-wide MouseArea is declared **before** the content, because z-order follows declaration order and it would otherwise swallow the buttons' own clicks. (3) The body is `Text.StyledText` — exactly the spec's `<b> <i> <u> <a> <img>` subset, where `RichText` is a whole HTML engine for no gain under the software backend — and the image is `sourceSize`-capped at its drawn 48px for the reason `ClipboardPicker` caps its preview: every pixel is decoded and scaled on the CPU, and `image` is whatever path the app handed over. The history panel deliberately gets none of this: an action expires with its notification. `de/.local/share/dbus-1/services/fr.emersion.mako.service` is a stub (`Exec=/bin/true`) that shadows the system mako activation file — prevents D-Bus from relaunching mako when qs restarts and momentarily drops the `org.freedesktop.Notifications` bus name.
- `Battery.qml` — bottom-right card, a companion to the bar's `battery` block (the bar colours its own block; this adds the toast and an at-a-glance gauge). Reads the `Power` singleton, which reads `/sys/class/power_supply/BAT0` + `AC/online` on a 10s timer (**upowerd is not running**, so `Quickshell.Services.UPower` reports nothing). Below 20% while discharging the readout+gauge+border turn red and one `notify-send -u critical` fires — latched, re-arming only above 25% or on charge, so a level hovering on the threshold can't spam it. **Two non-obvious bits:** (1) `stackLayer` is state-dependent — `Bottom` at rest like the other ambient cards, `Overlay` once low, because a Bottom-layer card is hidden behind any tiled window at exactly the moment it needs to be seen; (2) the `shell.qml` gate is `Config.on("battery") && Config.batteryPresent`, where `batteryPresent` is a `blockLoading` `FileView` probe of `BAT0/capacity` in `Config.qml` — so the desktop never *builds* the widget rather than building it and hiding it.
- `Brightness.qml` / `Sys.qml` / `CpuGraph.qml` — `Brightness` is a **readout, not a control**: reach owns gamma and publishes the level, so the card binds to `Reach.brightness` (no `brightness.sh get` poll, no subprocess) and the drag-to-set slider is gone, because the state socket is write-only and there is nothing for a drag to call — `Super+Alt+Left/Right` is the way to set it. Then CPU/RAM (native `/proc` reads on a 2s Timer) and disk / CPU temp / nvidia-smi GPU (three `Poll`s at the same 2s); `/proc/net/dev` + `ip -j addr` for net. Two things are gated on a one-shot probe rather than rediscovered per tick: `Sys`'s GPU read on `/proc/driver/nvidia/version` (on the laptop the 2s tick forked an `nvidia-smi` that can only fail, ~43k times a day) and `Power`'s timer on Config's BAT0 probe (the desktop reloaded two files that don't exist every 10s).
- `Mpd.qml` — **fully native, no subprocess polling**: transport/metadata/art/progress via `Quickshell.Services.Mpris` (follows the active MPRIS player, prefers a playing one then MPD — so it also drives Zen etc.; needs the `mpd-mpris` bridge in the `mpd` group service to put MPD on the MPRIS bus), volume/mute via the `Volume` singleton (Pipewire's default sink/source, kept live by its `PwObjectTracker`). Replaced the old `mpc`×4/s + `wpctl`×2/s polling.
- `Calendar.qml` — ICS agenda list in the left bar (reads `calendar.url` via `calendar.sh events`, every 5 min). The refresh button runs `calendar.sh refresh` as a one-shot `Poll` and takes its output as the new list. Colour by day: today red → six days out mauve; an event already under way (negative `days_from_today`) wraps round the table, which is what the script's Python negative indexing used to do.
- `Settings.qml` / `Config.qml` — the feature switchboard and its UI. `Config.overrides` is parsed from the state file by an **initial binding, not `Component.onCompleted`**: the first thing to touch the singleton is `shell.qml`'s `active:` binding, and `onCompleted` runs *after* that read — every disabled widget would be built and then immediately torn down. As a binding the first answer is already correct. `FileView` is `blockLoading` for the same reason (the flags are read in the frame the shell builds), `printErrors: false` because a missing file is the normal first-run state, and it creates its own parent directory on first write. Writing through `Config.setEnabled()` **replaces that binding for good**, which is deliberate: `setText()` is async (`text()` still returns the old value in the same tick), so a value bound to the file would fight every toggle — the menu owns it from then on. Toggles assign a fresh object rather than mutating, since QML only notifies on assignment and every `LazyLoader` is watching. A corrupt file logs and falls back to everything-on rather than taking the shell down.
- `Picker.qml` — shared base for the full-screen pickers (`Launcher`, `WallpaperPicker`, `ClipboardPicker`, `Audio`, `Network`, `Settings`): IPC toggle, one overlay per output, the focused-monitor pointer-latching, and **`hoverMoved(item, event)`**. It also owns what four pickers each used to re-type: `boxHeight` summed from `rows` (`headerHeight`/`rowHeight`/`barHeight`/`minBoxHeight`; a picker with no `rows` falls back to `heightFraction`, which is what `0` means), **`navKey(e)`** (Escape/Return/j/k/arrows — a picker handles only its own extra keys, and Return goes to its `activate(i)`), the `onRowsChanged` re-clamp of `selected` (Audio has the shell's most volatile rows and never had one), the `move()`/`count` navigation the self-driven pickers share, and taking keyboard focus — so `reset()` on the content now means only "my own extra state" (a query to clear, a password field to drop). The content `Loader` is **gated on the box being visible**: ungated, every picker's tree existed on every output for the whole session, and the wallpaper grid held its decoded thumbnails in all three. Every picker's list selects through `PickerHover.qml`, which asks `hoverMoved` before letting hover take the selection, because Qt delivers a hover move whenever the row *under* the cursor changes — so neither `entered` nor `positionChanged` means the user pointed at anything. Arrowing through a list scrolls it past a motionless pointer, and the row that slides underneath fires hover and hands the selection straight back (arrow down once, jump back to wherever the mouse is). `hoverMoved` compares **window-space** coordinates and is true only on real movement. `pointerSeen` is cleared on open so the first event merely records a baseline — an overlay maps under wherever the cursor already is, and without that `Super+Space` `Return` would launch, or the audio menu would switch a sink, that nobody pointed at. `Launcher` and `WallpaperPicker` both scroll via `positionViewAtIndex` and had the full bug; `Audio` doesn't scroll but had the open-under-cursor half.
- `Launcher.qml` — minimal drun app launcher (replaces `rofi -show drun`). Opens on the **focused monitor**: a full-screen overlay is mapped per output (`Variants` over `Quickshell.screens`), but the box is drawn only on the output whose overlay contains the pointer — under reach's `sloppy_focus` that IS the focused monitor. reach exposes **no IPC** for the focused output and grants keyboard focus to *every* layer surface, so pointer containment (a `hoverEnabled` MouseArea latching `activeScreen`) is what singles one out; `activeScreen` is blanked on open (150ms DP-2 fallback timer) to avoid flashing on the previously-focused monitor. Shared query/results/selection state lives on the `Scope` root. The filtered list is a **binding**, never a snapshot: `DesktopEntries` scans asynchronously (`applications.values` is empty at load and fills ~50ms later), so a list computed once when the box opened stayed empty for that whole open if you hit `Super+Space` right after a start or hot-reload — the symptom was an open launcher with a working query field and no rows. An empty result now says so ("no applications found" / "no matches") instead of rendering a blank box. Type to filter `DesktopEntries.applications` by name; Up/Down or Ctrl+K/J to move, Enter = `entry.execute()`, Esc / click-outside closes. Hover selection goes through `PickerHover` (see the `Picker.qml` entry). Triggered by `IpcHandler` target `"launcher"` (`toggle`/`hide`/`open`); `Super+space` = `qs ipc call launcher toggle`. A query starting with **`/`** switches it to file mode (see `FileIndex.qml`): Enter opens the hit in `kitty -e nvim` (a directory in `yazi` — nvim on one lands in the netrw that nvim-tree disables), `Shift+Enter` always opens `yazi` (on a file: its parent, with the file selected), `Ctrl+Enter` hands it to `xdg-open`, `Ctrl+T` opens `kitty --directory` in the containing directory, `Ctrl+Y` copies the path. yazi is launched as `kitty -e zsh -ic 'y "$1"; exec zsh'` rather than as kitty's command, so `q` leaves an interactive shell (in the directory yazi was left in, via the zshrc `y` wrapper's `--cwd-file`) instead of closing the window.

**Scripts** (`de/.config/quickshell/scripts/`): `monitors.py` (the ZON⇄JSON bridge for the display configurator, and the only thing that knows either the file format or the symlink convention: `state` merges the layout files in `~/.config/reach/monitors/` with `wlr-randr --json` and reports the link's target as the active one; `activate` re-points the link, `save` writes a layout file, `delete` removes one — all **atomically**, the symlink included (a new link under a temp name, renamed over the old one, since unlink-then-symlink leaves a window where a reload would find no layout at all), each followed by a SIGHUP. QML can neither parse nor write ZON, and reach cannot write its own config — its state socket is write-only — so this script is the one place that knows the format. It carries a small ZON reader for the subset the schema allows, and `save` takes its JSON as an argv argument rather than on stdin so the QML side is one `Process` launch rather than a launch plus a write), `calendar.sh` (Python; `events` = agenda list, `refresh` = drop the cache and print the same list (so the card's refresh button is one process, not a refresh racing an `events` read), `status`; each event carries `days_from_today` and **the card** maps it to a colour (`Calendar.qml`'s `dayColor`) — the script used to hold its own copy of seven palette hexes; needs `icalendar`+`recurring_ical_events` from home-manager; caches to `/tmp/eww-calendar.ics`. It **globs** the nix-profile site-packages version rather than pinning it — the path was hardcoded to `python3.13`, and when nix moved to 3.14 every command silently returned `[]`), `vpn-manager.sh` is **gone**: the lab tunnels are NM profiles now, so there is no root openvpn daemon to start, find or kill (see `Network.qml`).

**A file added to `music/` needs a `qmldir` line.** That directory is an explicit module, so anything not declared stops resolving — including from its siblings — and the error names the *type*, not the missing entry. Same failure shape as the next paragraph.

**Editing a `.js` library needs a real restart.** Quickshell hot-reloads QML on change, but a `.pragma library` file (`NetworkData.js`) stays cached in the running engine: new functions read as `TypeError: Property 'x' ... is not a function` even though the file on disk is correct and every `Configuration Loaded` looks clean. `SVDIR=~/.local/sv sv restart quickshell` is the fix — a QML-only edit does not need it.

**IPC gotcha:** `qs ipc call <target> show` collides with the `qs ipc show` subcommand — the CLI prints the target listing, exits 0, and never calls the handler. **`hide` and `toggle` are fine** (measured: `qs ipc call settings hide` reaches the handler; `… show` prints the listing). `Picker`, `Music` and `Monitors` therefore expose `toggle`/`hide` plus **`open`** — the non-colliding name for "up regardless" — and `Spotlight` uses `flash`/`dismiss`. `open` exists for the launcher's `>` list: picking "Music" out of a menu must raise that window, and `toggle` would shut it whenever it was already up, which for the two **windows** (music, displays) is the ordinary case rather than a corner one. The three handlers are separate — `Picker` covers network/clipboard/audio/wallpaperpicker/settings, and the two windows each carry their own — so a verb added to one reaches none of the others; `qs ipc show` is the check.

**Deps:** nvidia-smi, curl, python3+icalendar+recurring-ical-events. **No `jq`**: `NetGraph.qml` filters `ip -j` in JS through `Poll`'s `onJsonData`, and `flip.sh` reads `pactl list sink-inputs` with awk. (Mpd.qml no longer shells out to `mpc`/`wpctl` — it uses native Mpris + Pipewire; it does rely on an MPD→MPRIS bridge being on the bus.)

## Card layout

**Card layout** (unscaled units; `s()` shrinks it to 0.85 on the laptop). Left column, 420 wide: clock `0–150`, brightness `150–225`, calendar `225 → screen−600` (it absorbs the slack), then bottom-up weather `450–600`, mpd `300–450`, net `150–300`, cpu `0–150`. Right: notifications top, battery bottom. The numbers are a chain — moving one card means moving everything below it, which is why removing the ports card (it used to hold `300–450`) meant sliding mpd and weather down and shortening the calendar.
