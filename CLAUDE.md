# CLAUDE.md

Guidance for Claude Code when working in this repo.

> Per-app keybinding/setting tables that simply mirror a config file have been trimmed to keep this file small. When you need exact keys/values, read the config at the path noted in each section. What's kept here is context **not** derivable from the files themselves (platform quirks, migration debt, cross-component wiring).

## Overview

Personal dotfiles for a **Gentoo Linux** system. Wayland stack centered on **reach** (a custom **Zig** Wayland compositor; dwl-like — tags, master/stack tiling, regex window rules, an **in-process** someblocks-style status bar). GNU Stow manages all symlinks from `de/` → `$HOME`. Terminal is **kitty**. Theme is **Catppuccin Mocha (Mauve accent)** everywhere. UI aesthetic: **flat/sharp** — `border-radius: 0` explicitly everywhere.

System package manager is **Portage** (`emerge`). Elevation is **`doas`** (`app-admin/doas`) — there is **no `sudo`** installed, and no sudo->doas symlink. doas matches a command **as typed**, so `permit nopass` rules only fire on absolute paths; poweroff/reboot from the quickshell lock screen need `permit nopass miles cmd /usr/bin/poweroff` and `.../reboot` in `/etc/doas.conf`, and report the missing rule rather than acting without them. `xbps`/`pacman`/`paru`/AUR do **not** apply. Nix + home-manager runs **alongside** Portage for a curated package set (security tools, GUI apps, Python libs). Clean nix with `nix-collect-garbage -d`.

> **Migration note:** previously Void Linux. Some configs still carry stale Void-era bits — see [Stale leftovers](#stale-voiddwl-leftovers).

## Installation & Setup

Old `install*.sh` bootstrap scripts were **removed**. Setup: `git clone` → `cd dotfiles` → `stow de` → `home-manager switch`. `stow -D de` removes symlinks. reach is configured purely by `de/.config/reach/config.zon` (no build step here). User runit services are picked up by the `runsvdir ~/.local/sv` reach autostart launches.

## Nix / home-manager

Runs alongside Portage for packages not easily/freshly available via emerge. `home-manager switch` applies. Configs:
- `home-manager/home.nix` — main (GUI apps, Python); imports `default.nix`. **Intentionally minimal** — no longer manages GTK theming/cursors/fonts/Qt (those are stowed directly + pushed via `dconf load`). Sets only one session var: `XDG_DATA_DIRS=/usr/local/share:/usr/share:$HOME/.nix-profile/share`.
- `home-manager/default.nix` — thin entrypoint importing `modules/cyber.nix`.
- `home-manager/modules/cyber.nix` — security/pentest toolkit (`home.packages`): nmap, burpsuite, sqlmap, ffuf, feroxbuster, metasploit, hashcat, hydra, aircrack-ng, wireshark, bettercap, binaryninja-free, netexec, impacket, responder, etc. (full categorized list lives in the file).
- `home-manager/security-box/` — large per-category `*.nix` catalog, **NOT imported** by anything — staging/reference only.
- `nixpkgs/config.nix` — `{ allowUnfree = true; }` (needed for burpsuite, wpscan, binaryninja-free).
- `home.nix` Python set includes `icalendar`, `recurring-ical-events`, `x-wr-timezone` which power the quickshell calendar widget; `pipx` has tests disabled via override (suite breaks on newer `packaging`).

> `hashcat` is installed via nix but the comment recommends the **system** `hashcat` for OpenCL/GPU driver compat.

> **nix GL vs system nvidia:** anything needing OpenGL/EGL/NVENC must come from **Portage**, not nix. The nvidia driver is Portage-managed (`/usr/lib64/libEGL_nvidia.so.*`), but nix binaries run under nix's `ld.so`, which never searches `/usr/lib64` — so the vendor ICD at `/usr/share/glvnd/egl_vendor.d/10_nvidia.json` resolves to nothing and EGL init dies (`eglGetDisplay failed` → *"Your GPU may not be supported"*). Pointing `LD_LIBRARY_PATH` at `/usr/lib64` doesn't fix it: it shadows nix libs with system ones and breaks the app earlier. Bridging the two properly is what `nixGL` exists for, and it works by shipping a *nix-built* driver matching the running kernel module — not by reusing the system one. **OBS lives in Portage for this reason** (`media-video/obs-studio`, USE `nvenc wayland screencast pulseaudio`); keep it out of `home.nix` or `~/.nix-profile/bin` will shadow `/usr/bin` on PATH.

## reach Window Manager

**Config:** `de/.config/reach/config.zon` — ZON (Zig Object Notation), read **once at startup**. Every field optional → falls back to compiled-in default (`config.zig`). Lookup order (first wins): `$XDG_CONFIG_HOME/reach/config.zon`, `~/.config/reach/config.zon`, `/etc/reach/config.zon`. Colors `0xRRGGBB` (border) / `0xRRGGBBAA` (bar). Read the file for exact behavior/keybinds/rules; notes below cover the non-obvious wiring.

**Behavior:** `sloppy_focus=true` (focus follows mouse), `nmaster=1`, `mfact=0.55`, gaps 0/2, border only on focused window (`0x89b4fa` blue, 2px).

**Shake to find** — `.cursor.shake` no longer grows the cursor; it runs `.command` (`qs ipc call spotlight flash`, quickshell's `Spotlight.qml`). reach detects the gesture from raw evdev deltas and can do nothing more with it: `river_seat_v1.pointer_position` only arrives inside a manage sequence (`src/shake.zig` header), so reach never learns where the pointer *is*, and as river's WM client rather than the compositor it has no surface to draw on. Growing worked only because a cursor size is a bare number for `set_xcursor_theme`. `.speed` is gone from the schema and `.command` is new, so **binary and config.zon must land together** — an unknown key fails the whole ZON parse and drops reach to compiled-in defaults (no binds).

**Monitor layout** — array order defines numbering for `focusmon`/`tagmon` and the `.monitor` index in window rules:

| Idx | Name     | Res       | Pos        | Transform  | Notes                  |
|-----|----------|-----------|------------|------------|------------------------|
| 0   | DP-3     | 3440x1440 | 0,0        | rotate_180 | Primary ultrawide      |
| 1   | DP-2     | 3440x1440 | 0,1440     | normal     | Secondary UW           |
| 2   | DP-1     | 1920x1080 | 3440,1440  | rotate_270 | Vertical, 165 Hz       |
| 3   | HDMI-A-1 | 3840x2160 | 5000,0     | normal     | Laptop's external, 4K  |
| 4   | eDP-1    | 1920x1200 | 5960,2160  | normal     | Laptop screen, below ^ |

Every entry needs an explicit `.x`/`.y`. The defaults are `-1,-1`, which reach reads
as "don't send `set_position`" — river then auto-places the head wherever it likes
(it put HDMI-A-1 side-by-side with eDP-1, not above it). The laptop pair sits past
x=4520 so it never collides with the desktop's DP block.

**Env vars (set by reach `.env` block):** `XDG_CURRENT_DESKTOP=river`, `XDG_SESSION_TYPE=wayland`, `QT_QPA_PLATFORM=wayland`, `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus`. Does **not** set `QT_QPA_PLATFORMTHEME`/`QT_STYLE_OVERRIDE` (old dwl setupenv did) — re-export if Qt apps stop picking up qt6ct/Kvantum.

**Autostart** (`de/.config/reach/autostart.sh`) is minimal — most daemons moved to runit user services. It: pins `DBUS_SESSION_BUS_ADDRESS` to `$XDG_RUNTIME_DIR/bus`, starts `runsvdir $HOME/.local/sv` if not running and waits for the bus socket, runs `redshift.sh 4000` (2s delay), launches `kitty --class rmpc rmpc`, and `dconf load`s `~/.config/dconf/interface.dconf` into GNOME settings.

**Window rules** (match `app_id`/`title`; `^foo`=starts-with, `foo`=contains; `tags`=`1<<n` bitmask; `monitor`=array index): rmpc→mon 2 (DP-1), zen→tag 4 + switchtotag, mpv→tag 1 + switchtotag, `^steam`→tag 16, `^float`/pavucontrol→floating centered 50%×50%.

**Status bar** — **off** (`.bar = .{ .enabled = false }`). The bar is quickshell's now (`Bar.qml`); the baked-in someblocks engine and `de/.config/reach/blocks/` are **gone**. `enabled` is a field the reach binary must know: an unknown key fails the *whole* ZON parse, and reach then falls back to compiled-in defaults — no binds, no monitor layout — so the binary has to be installed before this config. Everything else under `.bar` (font/colors/delim/blocks) is inert while it's off, and the compiled-in bar is still there if it's flipped back on.

**State socket** (`src/ipc.zig`, new) — reach publishes what its bar used to draw, since nothing about desktops/focus/titles is reachable any other way: river is non-monolithic, reach *is* the WM, and there is no compositor-side workspace protocol for a panel to bind. A SOCK_STREAM unix socket at `$XDG_RUNTIME_DIR/reach.sock` emits one JSON line per **change**, each a *complete* snapshot (`{"desktops":9,"outputs":[{name,desktop,focused,fullscreen,occupied[],title,appId}]}`) — whole snapshots, not deltas, so a reconnecting client needs no resync and can't apply anything out of order. Published from the render cycle, the same beat that redrew the internal bar; composing is skipped entirely when no client is connected. **Deliberately write-only**: client fds are read only to notice a disconnect. A `view <n>` command for clickable desktop cells would have to name the output too — `action.view` acts on `query.selectedOutput()`, so a click on an unfocused monitor's bar would switch the focused one — and moving the selection is a focus-semantics decision, not one a status socket should make.

**Keybinds:** `Super`=Mod. A `.binds` block **replaces the entire** default action/spawn/chord keymap **except** the auto-generated per-tag digit binds (`Super`/`+Ctrl`/`+Shift` + `1`–`9` = view/toggle/move, never listed in config). See `config.zon` for the full map. Notable: launchers (`Super+Tab` kitty, `Super+Space` quickshell launcher (`qs ipc call launcher toggle`, replaced rofi), `Super+Shift+Escape` shell settings (`qs ipc call settings toggle`), `Super+V` clipfzf, `Super+X` killfzf, `Super+Z` svfzf), `Super+r`/`Super+s` two-key chords (apps — incl. `a` = audio mixer, `n` = network menu / screenshots), `Alt+[` cycle EQ sink, `Super+Alt+Left/Right` brightness, `Super+Alt+Up` night-light toggle, `Super+P` lock (`qs ipc call lock lock`; the lock screen also carries poweroff/reboot/logout), `Super+b` random wallpaper (`qs ipc call wallpaper random`).

## Quickshell Desktop Widgets

**Config:** `de/.config/quickshell/` — QML components + `scripts/` (data providers). Entry point: `shell.qml` (`ShellRoot`), where each feature is one `LazyLoader { active: Config.on("<key>"); <Component>{} }` line — a feature toggled off is **never built** (zero RAM, no daemon), and toggling one at runtime builds or tears it down live, no restart. `active:` is synchronous on purpose (an all-`activeAsync` shell would never load — async loading needs an existing window first). Written in QML/Qt Quick; no separate daemon/open split — `qs` runs in the foreground and runsv supervises it directly.

**Which features are on is per-machine state, not config.** `Config.qml` holds a **catalogue** (`features`: one `{key, group, label}` entry per feature, in menu order) and nothing else; the on/off values live in `~/.local/state/quickshell/features.json`, which is **outside the repo** — not stowed, not committed — so one config serves the desktop and the laptop and each keeps its own set. **Only the OFF switches are stored**: anything absent is on, a missing file means the whole shell, and deleting the file restores everything. Edit it through the settings menu (`Super+Shift+Escape` / `qs ipc call settings toggle`), not by hand — hand-edits only land on the next start or QML reload. Adding a feature is one catalogue entry plus one `shell.qml` line; the menu is generated from the catalogue, so there is no second list to keep in sync.

**Service:** `~/.local/sv/quickshell/run` — waits for dbus+wayland sockets, sets `QT_QPA_PLATFORM=wayland`, `exec qs`. It also sets `QT_QUICK_BACKEND=software` (see **Rendering** below). Unlike eww, no monitor/scale detection in the shell script — that logic lives in `Config.qml` (`DP-2` present → scale 1.0, else 0.85).

**Components (shell.qml, gated by Config flags):** `WallpaperView` (per-screen wallpaper, replaces awww), `NotificationPopups` (toasts, replaces mako popups), `Session` (idle+lock screen, session actions on it; replaces swaylock+swayidle), `Clipboard` (cliphist text+image watchers, replaces the runit cliphist service), `Clock`, `CpuGraph`, `NetGraph`, `Ports`, `Vpn`, `Mpd`, `Weather`, `Notifications` (history panel + DND), `Calendar`, `Brightness`, `Battery` (laptop low-charge warning), `Spotlight` (shake-to-find cursor), `Launcher` (drun app launcher, replaces rofi), `Network` (Wi-Fi + VPN menu, replaces nmtui), `Bar` (the status bar, replaces reach's baked-in one), `Audio` (sink/source + per-app mixer, replaces pulsemixer), `Settings` (feature switchboard — the one component with no flag, since disabling it would leave no way back). The `tray` flag has no component of its own: the system tray is a section of `Bar.qml`.

**Shared pieces** (what a new widget should reach for before writing its own):
- `Config.qml` — besides the feature catalogue: `Config.scale` / `Config.s(n)` (the one 0.85-on-laptop factor; `Widget` forwards `s()` so cards call it unqualified) and `Config.screen(name)` (the output or null — the "which monitor" loop used to be open-coded in four places).
- `Theme.qml` — the palette plus `rowSelectBg`/`rowSelectFg`, the picker's selected-row colours that four files had spelled out as `#11111b`/`#bac2de`.
- `Widget.qml` — the card chrome (pin to the main screen, flat border, padding, Bottom layer). `Txt.qml`, `HeaderBtn.qml`, `Graph.qml` are the small shared visuals.
- `Poll.qml` — Timer+Process+StdioCollector in one. `onData` gives raw stdout; **`onJsonData` gives parsed JSON or null**, which is what the four JSON-producing pollers use instead of each writing the same try/catch.
- `Picker.qml` — full-screen overlay pickers: IPC toggle, focused-monitor latching, `hoverMoved`, and the shared `rows`/`selected`/`move()`/`firstSelectable()` list navigation that steps over `kind: "header"` entries (Settings and Audio had identical copies).
- `Sys.qml` — CPU/RAM/disk/GPU **and the battery** (`batteryPresent`/`batteryLevel`/`batteryStatus`/`charging`). One 10s poll of the BAT0 sysfs pair serves both the bar block and the corner card, which used to poll it separately at 30s and 10s.
- `Volume.qml` — the default sink/source and their volume/muted/name, with the one `PwObjectTracker` that keeps them bound. The bar, `Mpd.qml` and `Osd.qml` each carried a copy of that block; `Audio.qml` still talks to Pipewire directly, since the mixer is about the whole graph rather than the defaults.

**Rendering:** `QT_QUICK_BACKEND=software` in the service script. The shell is flat rectangles, text and one wallpaper blit, but the GL scenegraph gives **every visible window** its own render thread and Mesa context, and there are ~15 of them (a wallpaper and a bar per output, plus one per ambient card) — 589 MB RSS / 135 threads on the AMD laptop, against 260 MB / 22 with QPainter. The cost is that GPU-only QML types silently draw nothing: no `ShaderEffect`, `layer.effect` or `MultiEffect` in here (`TrayMenu.qml` tints its icons with `QtQuick.Controls.impl`'s `ColorImage`, which recolours on the CPU, for exactly this reason). Drop the line if a wallpaper crossfade ever stutters on the 3×3440x1440 desktop.

**Notable wiring:**
- `Bar.qml` / `Reach.qml` — the status bar, one per output, replacing the one reach drew itself; same layout (`[desktops] [title … app_id] [status]`), same colours, same hide-vacant/focused-monitor-highlight rules (reach's occupied-corner box was dropped — the cell being drawn at all already says it), so the switch is invisible. `Reach.qml` is the singleton holding window-manager state from reach's socket (see **State socket** above); `forScreen(name)` is how each bar finds its own output. Non-obvious bits: (1) it is an ordinary **layer surface**, so its `exclusiveZone` reserves the strip and the compositor pushes windows *and* the other quickshell cards below it — reach's bar was a river shell surface and had to subtract itself from the layout by hand (`Output.usableArea`). (2) The socket retry is driven by `running: !sock.connected`, **not** by `onConnectionStateChanged`: a connect that *fails* never entered the connected state, so there is no state change to hear and the first attempt would be the only one — the bar would stay blank for the whole session. 5s, only to keep the log quiet (each failure logs); the normal path never retries, since reach's autostart starts runsvdir and is listening before quickshell exists. (3) Hidden (`visible: false`, which releases the exclusive zone with it) when a window is fullscreen on that output, matching reach. (4) The status side is native — volume/mic from the `Volume` singleton, battery from `Sys`, clock in QML, one `sh -c` for the default-route IP — which is what retired the six block scripts and the `kill -35`/`-36` refresh binds.
- `Spotlight.qml` — dims every output and leaves a clear, feathered circle around the pointer (PowerToys' Find My Mouse), fired by reach's shake detector. Non-obvious bits: (1) **the overlay must accept input**, because that is the only way any Wayland client can learn the cursor position — the `enter` event carries surface-local coords. So it swallows clicks while mapped, which is why it is transient and dismisses on any key, any click, or ~60px of movement, with a 4s safety timeout. (2) Movement-dismiss is armed only after a 600ms grace period: the gesture that summons it *is* the pointer moving, so without that the shake would dismiss it in the same frame. (3) Under `QT_QUICK_BACKEND=software` there is no `ShaderEffect` to punch a hole with, so the wash is four plain `Rectangle`s around a square gap plus one small `Canvas` filling that square (`destination-out` = `QPainter::CompositionMode_DestinationOut`). The Canvas image is **position-independent**, so it paints once and is only ever moved — nothing repaints a screenful of pixels on the CPU as the pointer travels.
- `Session.qml` — the lock screen *is* the power menu. `Super+P` locks (`qs ipc call lock lock`), `IdleMonitor` locks at 300s, `WlSessionLock` (ext-session-lock) + PAM unlocks — and the surface carries Power off / Reboot / Log out under the password field. Three files collapsed into this one (`Lock.qml`, `PowerMenu.qml`): a menu offering "Lock" and a lock screen offering nothing were two halves of the same thing, and the `power` IPC target is gone with the overlay. Non-obvious bits: (1) the password field **keeps focus permanently** — arrows and Tab arm an action from inside its `Keys.onPressed` rather than moving focus (Down/Right step into the row, Up/Left back out to the field), so a password typed at any moment still lands in the box it was meant for, and typing disarms (a stray Tab can't turn the next Return into a poweroff); nothing fires on one keystroke or one click, it's arm-then-confirm. (2) poweroff/reboot run `doas -n /usr/bin/<cmd>` and **need a `permit nopass` rule** — the old unlocked menu could spawn a floating kitty for doas's password prompt, but the lock surface sits above every window, so that prompt would be invisible and unfocusable there. `-n` fails fast instead of hanging on a prompt no one can reach, and the surface says so rather than doing nothing. The absolute path matters: doas matches the command as typed.
- `Audio.qml` — `Picker`-based mixer: output devices, input devices, and a volume row per playing app (`Super+R` `A` / `qs ipc call audio toggle`; replaced `kitty --class float -e pulsemixer`). Rows are classified by `media.class`, **not** `isSink`/`isStream` — a playback stream reports `isSink` true as well, since it feeds one. App streams are those carrying an `application.name`; that is exactly what excludes the EQ filter-chains' own `effect_output.*` playback streams and the mic loopback, which must never be dragged along when streams migrate. `PwObjectTracker` stays armed on all nodes rather than being gated on `open`, because a node only publishes `.audio` while something holds a binding and the menu has to be right in the frame it opens. Picking a **sink** shells out to `flip.sh set <name>` instead of setting `Pipewire.preferredDefaultAudioSink` — the optical chain needs a card-profile flip first and existing streams need moving by hand, and that logic already lives in the script `Alt+[` uses. Sources just set `preferredDefaultAudioSource`. The current default sink/source carries a mauve wash plus a left accent bar, brightening when selected rather than being covered by the selection band — tinting only its icon was invisible under the cursor. Keys: `j`/`k` select, `h`/`l` volume ±5%, `m` mute, `Return` activate.
- `Network.qml` — `Picker`-based Wi-Fi + VPN menu (`Super+R` `N` / `qs ipc call network toggle`), replacing the floating kitty running nmtui. Non-obvious bits: (1) **two kinds of VPN, on purpose.** `wireguard` is a NetworkManager profile (`nmcli con up/down`), but `~/VPNs/*.ovpn` are run by `scripts/vpn-manager.sh` as a bare root openvpn daemon NM knows nothing about — it surfaces as an *externally connected* `tun0` and would drop out of an nmcli-only menu while still carrying traffic, so both are listed and each is toggled the only way it can be. (2) The homelab tunnel — the NM `wireguard` profile, from the root-only `/etc/wireguard` config — is named in one `alwaysOn` list (by NM *connection* name, the only name the rows carry); it gets its own section, a red **down** marker, and the warning line. The `~/VPNs/*.ovpn` profiles are HackTheBox/TryHackMe labs and fall into "Labs". **Enter only ever connects, `d` disconnects**, for every row kind: toggling on Return put the always-on tunnel one stray keystroke from being dropped. (3) Nothing elevates — `con up`/`con down`/`device wifi connect` are all fine unprivileged, and the menu never runs `con mod`, which needs doas and would silently destroy stored secrets without it. (4) NM connections are acted on by **UUID**, never by name (`con up id <name>` is ambiguous — several connections may share a name), and a VPN row whose *device* reads `connected (externally)` is labelled **external**: that is NM describing a `wg-quick` link it merely assumed, backed by a volatile profile in `/run`, not a profile you saved. (5) Joining is `nmcli device wifi connect <ssid>`, **never** by connection name: eduroam's profile is named `eduroam [a8f5604d]`, so name-matching would miss it and create a second profile. NM asks for a key by *failing*, so a secrets error grows a password field in the bottom bar and retries once (the key rides in argv — nmcli takes it no other way). (6) Connections, devices and the radio switch share one tagged `sh -c` (~25ms) because they're one snapshot and separate timers show a torn one — but **the AP list is deliberately not in it**. `nmcli device wifi list` defaults to `--rescan auto`, which **blocks ~3.4s** whenever the scan cache is over 30s old (24ms when fresh), and as the last command in the shared `sh -c` it held the whole snapshot back: an open with a cold cache drew a menu with no Wi-Fi *and* no wired rows, leaving only the rows from the separate `vpn-manager.sh` poll. So it's its own `Poll` with `--rescan no` (cache read, always instant), and the scan request goes out detached on a 15s timer, with the next tick collecting the results. All polls are `running: root.open`, so a closed menu costs nothing. nmcli's terse output escapes `:` as `\:`, so the parser unescapes rather than plain-splitting.
- `Wallpaper.qml` / `WallpaperView.qml` — singleton; `IpcHandler` target `"wallpaper"` → `random` or `set <path>`; `Super+b` = `qs ipc call wallpaper random`; picks from `~/Pictures/bgs`. **RAM-critical:** the `Image` layers use `cache: true` + a single shared `sourceSize` (`Wallpaper.decodeSize`, the global max output WxH) so **all outputs share ONE decoded buffer** via `QQuickPixmapCache` — do **not** set `cache: false` or per-output `sourceSize` (that's what made every monitor hold its own copy, ~114 MB). The two crossfade layers free their source once faded out, so steady state holds a single buffer. GPU textures are still per-window but live in VRAM (nvidia), not RSS.
- `Clipboard.qml` — `Scope` with two self-restarting `Process` watchers (`wl-paste --type text/image --watch cliphist store`); inherits qs's `WAYLAND_DISPLAY` (no socket-wait needed). Replaced the runit `cliphist` group service. Picker (`clipfzf`, `Super+V`) unchanged — still reads `cliphist list`.
- `NotificationPopups.qml` — uses `Quickshell.Services.Notifications` (FreeDesktop D-Bus server). `de/.local/share/dbus-1/services/fr.emersion.mako.service` is a stub (`Exec=/bin/true`) that shadows the system mako activation file — prevents D-Bus from relaunching mako when qs restarts and momentarily drops the `org.freedesktop.Notifications` bus name.
- `Battery.qml` — bottom-right card, a companion to the bar's `battery` block (the bar does its own red via `^fg()` markup; this adds the toast and an at-a-glance gauge). Reads `/sys/class/power_supply/BAT0` on a 10s timer (**upowerd is not running**, so `Quickshell.Services.UPower` reports nothing). Below 20% while discharging the readout+gauge+border turn red and one `notify-send -u critical` fires — latched, re-arming only above 25% or on charge, so a level hovering on the threshold can't spam it. **Two non-obvious bits:** (1) `stackLayer` is state-dependent — `Bottom` at rest like the other ambient cards, `Overlay` once low, because a Bottom-layer card is hidden behind any tiled window at exactly the moment it needs to be seen; (2) the `shell.qml` gate is `Config.battery && Config.batteryPresent`, where `batteryPresent` is a `blockLoading` `FileView` probe of `BAT0/capacity` in `Config.qml` — so the desktop never *builds* the widget rather than building it and hiding it.
- `Brightness.qml` / `Sys.qml` / `CpuGraph.qml` — brightness via wl-gammarelay-rs; CPU/RAM/disk + nvidia-smi GPU; `/proc/net/dev` + `ip -j addr` for net.
- `Mpd.qml` — **fully native, no subprocess polling**: transport/metadata/art/progress via `Quickshell.Services.Mpris` (follows the active MPRIS player, prefers a playing one then MPD — so it also drives Zen etc.; needs the `mpd-mpris` bridge in the `mpd` group service to put MPD on the MPRIS bus), volume/mute via `Quickshell.Services.Pipewire` (`defaultAudioSink`/`defaultAudioSource` + a `PwObjectTracker` to keep `.audio.volume`/`.muted` live). Replaced the old `mpc`×4/s + `wpctl`×2/s polling.
- `Calendar.qml` — ICS agenda list in the left bar (reads `calendar.url` via `calendar.sh events`).
- `Settings.qml` / `Config.qml` — the feature switchboard and its UI. `Config.overrides` is parsed from the state file by an **initial binding, not `Component.onCompleted`**: the first thing to touch the singleton is `shell.qml`'s `active:` binding, and `onCompleted` runs *after* that read — every disabled widget would be built and then immediately torn down. As a binding the first answer is already correct. `FileView` is `blockLoading` for the same reason (the flags are read in the frame the shell builds), `printErrors: false` because a missing file is the normal first-run state, and it creates its own parent directory on first write. Writing through `Config.setEnabled()` **replaces that binding for good**, which is deliberate: `setText()` is async (`text()` still returns the old value in the same tick), so a value bound to the file would fight every toggle — the menu owns it from then on. Toggles assign a fresh object rather than mutating, since QML only notifies on assignment and every `LazyLoader` is watching. A corrupt file logs and falls back to everything-on rather than taking the shell down.
- `Picker.qml` — shared base for the full-screen pickers (`Launcher`, `WallpaperPicker`, `Audio`): IPC toggle, one overlay per output, the focused-monitor pointer-latching, and **`hoverMoved(item, event)`**. Every picker's list asks `hoverMoved` before letting hover take the selection, because Qt delivers a hover move whenever the row *under* the cursor changes — so neither `entered` nor `positionChanged` means the user pointed at anything. Arrowing through a list scrolls it past a motionless pointer, and the row that slides underneath fires hover and hands the selection straight back (arrow down once, jump back to wherever the mouse is). `hoverMoved` compares **window-space** coordinates and is true only on real movement. `pointerSeen` is cleared on open so the first event merely records a baseline — an overlay maps under wherever the cursor already is, and without that `Super+Space` `Return` would launch, or the audio menu would switch a sink, that nobody pointed at. `Launcher` and `WallpaperPicker` both scroll via `positionViewAtIndex` and had the full bug; `Audio` doesn't scroll but had the open-under-cursor half.
- `Launcher.qml` — minimal drun app launcher (replaces `rofi -show drun`). Opens on the **focused monitor**: a full-screen overlay is mapped per output (`Variants` over `Quickshell.screens`), but the box is drawn only on the output whose overlay contains the pointer — under reach's `sloppy_focus` that IS the focused monitor. reach exposes **no IPC** for the focused output and grants keyboard focus to *every* layer surface, so pointer containment (a `hoverEnabled` MouseArea latching `activeScreen`) is what singles one out; `activeScreen` is blanked on open (150ms DP-2 fallback timer) to avoid flashing on the previously-focused monitor. Shared query/results/selection state lives on the `Scope` root. The filtered list is a **binding**, never a snapshot: `DesktopEntries` scans asynchronously (`applications.values` is empty at load and fills ~50ms later), so a list computed once when the box opened stayed empty for that whole open if you hit `Super+Space` right after a start or hot-reload — the symptom was an open launcher with a working query field and no rows. An empty result now says so ("no applications found" / "no matches") instead of rendering a blank box. Type to filter `DesktopEntries.applications` by name; Up/Down or Ctrl+K/J to move, Enter = `entry.execute()`, Esc / click-outside closes. Hover selection goes through `Picker.hoverMoved` (see the `Picker.qml` entry). Triggered by `IpcHandler` target `"launcher"` (`toggle`/`show`/`hide`); `Super+space` = `qs ipc call launcher toggle`.

**Scripts** (`de/.config/quickshell/scripts/`): `calendar.sh` (Python; `events` = agenda list, `week [offset]` = grid geometry, `refresh`, `status`; needs `icalendar`+`recurring_ical_events` from home-manager; caches to `/tmp/eww-calendar.ics`. It **globs** the nix-profile site-packages version rather than pinning it — the path was hardcoded to `python3.13`, and when nix moved to 3.14 every command silently returned `[]`), `ports.sh` (ss+jq), `vpn-manager.sh` (OpenVPN; **status comes from the process table**, not a marker file — `openvpn --daemon` forks before `--writepid` lands, so the old `/tmp/eww-openvpn.status` was never written, `status` always printed `""`, every UI showed a live tunnel as down, and a connect stacked a *second* daemon on the first (two `tun` devices, one untracked); `connect` now refuses a config that already has a daemon and `disconnect` kills every matching one, so it also cleans up an orphan. Still the only way the `~/VPNs/*.ovpn` tunnels are managed — `Network.qml` calls it for those rows, and `Vpn.qml`'s bottom-left card is now redundant with that menu).

**IPC gotcha:** `qs ipc call <target> show` (and `hide`) collides with the `qs ipc show` subcommand — the CLI prints the target listing, exits 0, and never calls the handler. Name IPC functions something else (`Spotlight` uses `flash`/`dismiss`); `toggle` is unaffected.

**Deps:** jq, wl-gammarelay-rs+gdbus, nvidia-smi, curl, python3+icalendar+recurring-ical-events. (Mpd.qml no longer shells out to `mpc`/`wpctl` — it uses native Mpris + Pipewire; it does rely on an MPD→MPRIS bridge being on the bus.)

## Services (runit)

Two scopes, managed by `svfzf` (user, `Super+Z`) / `ssvfzf` (system, `doas`) or `sv` directly.

**User** (`~/.local/sv`, supervised by per-user `runsvdir` from reach autostart; disable = drop a `down` file): `dbus` (persistent user D-Bus **session** bus — whole stack inherits it), `pipewire` (**group service**: pipewire + wireplumber + pipewire-pulse), `mpd` (**group service**: mpd + mpd-mpris), `emacs`, `quickshell` (widgets + wallpaper + lock + notifications + **clipboard/cliphist watchers**), `syncthing`, `wl-gammarelay-rs`. Manage via `svfzf` or `SVDIR=~/.local/sv sv <cmd> <name>`. **Group services** run several related daemons from one `run` script (`wait -n` → kill the group → runsv respawns all together), so a crash of any one restarts the set as a unit. (Clipboard capture used to be a standalone `cliphist` group service — now owned by quickshell's `Clipboard.qml`.)

**System** (`/etc/sv` → `/service`, **outside this repo**, not stowed): enable/disable via the `/service` symlink. Inspect on-box; typically greetd/tuigreet, ufw, bluetooth, dbus, udisks2.
