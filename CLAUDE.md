# CLAUDE.md

Guidance for Claude Code when working in this repo.

> Per-app keybinding/setting tables that simply mirror a config file have been trimmed to keep this file small. When you need exact keys/values, read the config at the path noted in each section. What's kept here is context **not** derivable from the files themselves (platform quirks, migration debt, cross-component wiring).

## Overview

Personal dotfiles for a **Gentoo Linux** system. Wayland stack centered on **reach** (a custom **Zig** river window manager; dwl-like — desktops, master/stack tiling, window rules; it draws no bar — state goes out over a socket for quickshell to draw). GNU Stow manages all symlinks from `de/` → `$HOME`. Terminal is **kitty**. Theme is **Catppuccin Mocha (Mauve accent)** everywhere. UI aesthetic: **flat/sharp** — `border-radius: 0` explicitly everywhere.

System package manager is **Portage** (`emerge`). Elevation is **`doas`** (`app-admin/doas`) — there is **no `sudo`** installed, and no sudo->doas symlink. doas matches a command **as typed against the rule as written** — `/etc/doas.conf` here carries `permit nopass :wheel cmd poweroff` (bare names, and miles is in `wheel`), so a caller must invoke the bare `poweroff`; passing `/usr/bin/poweroff` misses that rule and falls through to `permit persist :wheel`, which wants a password. (The `openvpn`/`kill` rules were written as absolute paths and needed the opposite — **the shell no longer uses either**: VPNs went NM-native, so nothing it runs elevates.) Check any invocation with `doas -C /etc/doas.conf <cmd>` — it prints `permit` / `permit nopass` / `deny` and executes nothing. `xbps`/`pacman`/`paru`/AUR do **not** apply. Nix + home-manager runs **alongside** Portage for a curated package set (security tools, GUI apps, Python libs). Clean nix with `nix-collect-garbage -d`.

> **Migration note:** previously Void Linux. Some configs still carry stale Void-era bits — see [Stale leftovers](#stale-voiddwl-leftovers).

## Installation & Setup

Old `install*.sh` bootstrap scripts were **removed**. Setup: `git clone` → `cd dotfiles` → `stow de` → `home-manager switch --flake ~/.config/home-manager#miles` (home-manager is a **flake** now — a bare `home-manager switch` has no config to find; the `nixup` alias is the update form). `stow -D de` removes symlinks. reach is configured purely by `de/.config/reach/config.zon` (no build step here). User runit services are picked up by the `runsvdir ~/.local/sv` reach autostart launches.

## Nix / home-manager

Runs alongside Portage for packages not easily/freshly available via emerge. It is a **flake** (`home-manager/flake.nix`, `homeConfigurations."miles"`, nixpkgs `nixos-unstable`): apply with `home-manager switch --flake ~/.config/home-manager#miles`, update with the `nixup` alias (`nix flake update` + switch). Configs:
- `home-manager/flake.nix` — inputs + `config.allowUnfree` + the **overlay**, which is where per-package breakage gets pinned down: `pipx` tests off, `evil-winrm` built against Ruby 3.3 (Ruby 3.4 dropped `csv` from default gems and its gemset lacks it), and a `pythonPackagesExtensions` override re-fetching `playwright` (nixpkgs pins a GitHub-generated tarball hash that GitHub regenerated — the fixed-output fetch fails and takes theharvester → `home-manager-path` → the whole generation with it, which is why a switch right after a flake update dies with *hash mismatch in fixed-output derivation*). Each override carries its reason in a comment; read them before dropping one.
- `home-manager/home.nix` — main (GUI apps, Python); imports `default.nix`. **Intentionally minimal** — no longer manages GTK theming/cursors/fonts/Qt (those are stowed directly + pushed via `dconf load`). Sets only one session var: `XDG_DATA_DIRS=/usr/local/share:/usr/share:$HOME/.nix-profile/share`. Declares `nix` itself in `home.packages` — home-manager rebuilds `~/.nix-profile` from that list on every switch, so an undeclared `nix` gets wiped off a single-user install. Also symlinks `proton-ge-bin`'s steamcompattool into Steam's `compatibilitytools.d` via `home.file` (its default output is a bare file, so it can't go in `home.packages`).
- `home-manager/default.nix` — thin entrypoint importing `modules/cyber.nix` + `modules/webdev.nix`.
- `home-manager/modules/webdev.nix` — course web toolchain: `nodejs_24` (pinned to the major), `mongodb-ce` (**not** `mongodb` — that builds the server from source via scons; the `-ce` attr unpacks upstream's prebuilt tarball), mongosh/tools, the html/css/json/eslint/ts LSPs the nvim setup expects, prettier, httpie.
- `home-manager/modules/virt.nix` — virt-manager/virt-viewer/spice-gtk. **NOT imported** by `default.nix`; add the import to use it.
- `home-manager/modules/cyber.nix` — security/pentest toolkit (`home.packages`): nmap, burpsuite, sqlmap, ffuf, feroxbuster, metasploit, exploitdb, hashcat, hydra, aircrack-ng, wireshark, bettercap, binaryninja-free, netexec, impacket, responder, etc. (full categorized list lives in the file). `netexec` is wrapped in an `overrideAttrs` that patches the `signing` kwarg out of `nxc/protocols/ldap.py` — nixpkgs pairs it with an impacket whose `LDAPConnection` has no such parameter, so every `nxc ldap` dies in `check_ldap_signing` with a TypeError. Also defines the `my.cyberPythonLibs` option consumed by `home.nix`.
- `home-manager/security-box/` — large per-category `*.nix` catalog, **NOT imported** by anything — staging/reference only.
- `nixpkgs/config.nix` — `{ allowUnfree = true; }` (burpsuite, wpscan, binaryninja-free). The flake sets `config.allowUnfree` itself, so this file only matters to `nix-env`/`nix shell` outside the flake.
- `home.nix` Python set includes `icalendar`, `recurring-ical-events`, `x-wr-timezone` which power the quickshell calendar widget, plus `config.my.cyberPythonLibs` — an option `cyber.nix` defines, so the pentest libraries (impacket, ldap3, pywinrm, …) land in the **same** interpreter as everything else instead of a second `python3.withPackages`.

> `hashcat` is installed via nix but the comment recommends the **system** `hashcat` for OpenCL/GPU driver compat.

> **nix GL vs system nvidia:** anything needing OpenGL/EGL/NVENC must come from **Portage**, not nix. The nvidia driver is Portage-managed (`/usr/lib64/libEGL_nvidia.so.*`), but nix binaries run under nix's `ld.so`, which never searches `/usr/lib64` — so the vendor ICD at `/usr/share/glvnd/egl_vendor.d/10_nvidia.json` resolves to nothing and EGL init dies (`eglGetDisplay failed` → *"Your GPU may not be supported"*). Pointing `LD_LIBRARY_PATH` at `/usr/lib64` doesn't fix it: it shadows nix libs with system ones and breaks the app earlier. Bridging the two properly is what `nixGL` exists for, and it works by shipping a *nix-built* driver matching the running kernel module — not by reusing the system one. **OBS lives in Portage for this reason** (`media-video/obs-studio`, USE `nvenc wayland screencast pulseaudio`); keep it out of `home.nix` or `~/.nix-profile/bin` will shadow `/usr/bin` on PATH.

## reach Window Manager

**Config:** `de/.config/reach/config.zon` — ZON (Zig Object Notation), **live-reloadable**: `Super+Shift+r` (`.reload`) or `kill -HUP $(pidof reach)` re-reads it, and the monitor layout comes with it — but only when the `.monitors` block actually **changed by value** (`reload.zig` diffs the two generations while both arenas are alive; re-applying an unchanged mode set is a visible flicker for nothing). When it has, `outputconfig.reapply()` reuses the last output-manager serial rather than waiting for a `done` that editing a file never triggers; a stale serial gets `cancelled`, which re-arms the normal path. Each load parses into its own arena against a snapshot of the compiled-in defaults, so reload is idempotent and a field dropped from config.zon returns to its default instead of keeping the old value. A reload is only *requested* from the signal/keybind handler and applied at the top of the next manage cycle. A parse error leaves the running config alone, so a typo is survivable — but note the unknown-key trap below still applies at **startup**, where the fallback is the compiled-in defaults (no binds). `env` and `autostart` are deliberately **startup-only** — the variables went into a process tree that already exists and the programs already ran, so a reload logs that it skipped them rather than duplicating them. Every field optional → falls back to compiled-in default (`config.zig`). Lookup order (first wins): `$XDG_CONFIG_HOME/reach/config.zon`, `~/.config/reach/config.zon`, `/etc/reach/config.zon`. Colors `0xRRGGBB` (border) / `0xRRGGBBAA` (bar). Read the file for exact behavior/keybinds/rules; notes below cover the non-obvious wiring.

**Behavior:** `sloppy_focus=true` (focus follows mouse), `nmaster=1`, `mfact=0.6`, gaps 0/0, borders 5px — `border_active` `0xcba6f7` (mauve), `border_inactive` `0x45475a` (surface1). Unfocused windows *do* carry a border now (it used to be focus-only, blue, 2px); the accent moved to mauve to match the rest of the theme.

**Shake to find** — `.cursor.shake` no longer grows the cursor; it runs `.command` (`qs ipc call spotlight flash`, quickshell's `Spotlight.qml`) once the gesture has been held `.delay` ms (450). reach detects the gesture from raw evdev deltas and can do nothing more with it: `river_seat_v1.pointer_position` only arrives inside a manage sequence (`src/shake.zig` header), so reach never learns where the pointer *is*, and as river's WM client rather than the compositor it has no surface to draw on. Growing worked only because a cursor size is a bare number for `set_xcursor_theme`. `.speed` is gone from the schema and `.command` is new, so **binary and config.zon must land together** — an unknown key fails the whole ZON parse and drops reach to compiled-in defaults (no binds).

**Gamma (dimming + night light)** — reach owns the screen's gamma ramps itself (`src/gamma.zig`, `protocol/wlr-gamma-control-unstable-v1.xml`), which **replaced `wl-gammarelay-rs`** and the two scripts that drove it. Two knobs, deliberately asymmetric: **brightness** is runtime state with a keybind and no config field (`.{ .brightness = ±5 }`, applied to every output in-process — no script, no daemon, no bus round trip, floored at 10% so a key can never black the screen out), and **temperature** is a config field with no action (`.gamma = .{ .temperature = 4000 }`; a reload *is* the night-light switch). Non-obvious bits: (1) **why the WM.** `zwlr_gamma_control_v1` is held, not set — the client keeps the object alive for as long as the adjustment lasts, the compositor restores the original ramp the instant it dies, and only one client per output may hold one. So the owner has to be the longest-lived process in the session. (2) That exclusivity means **wl-gammarelay-rs (or wlsunset/gammastep) must not be running**, or reach's controls come back `failed` and dimming silently does nothing — the log says so. (3) Ramps are normalised against 6500 K, so "neutral" is an exact identity table rather than a faint cast; the colour math is the Kim et al. Planckian fit redshift and wlsunset use, **then gamma-encoded** — the fit gives multipliers in linear light, a ramp holds encoded values, and attenuating an encoded `v` by a linear `f` needs `f^(1/2.2)·v`. Applied raw, 4000 K sends `1.000/0.692/0.380` instead of `1.000/0.846/0.644` (redshift's table), which reads as a screen both far redder *and* much darker than asked for, since green carries most of the perceived luminance. A test pins 4000 K against that table. (4) The table goes over a **memfd**, not `wl_shm` — `set_gamma` takes a bare fd — and reach closes its copy right after, which is correct rather than a double close because libwayland dups the fd while marshalling. (5) It is re-asserted on a `dimensions` change, since a mode set can land after the ramp was written. (6) **It cannot be tested in a nested session**: the wayland and headless backends have no hardware LUT, so every output there answers `failed`.

**Monitor layout** — array order defines numbering for `focusmon`/`tagmon` and the `.monitor` index in window rules:

| Idx | Name  | Res       | Pos       | Transform  | Notes                       |
|-----|-------|-----------|-----------|------------|-----------------------------|
| 0   | DP-3  | 3440x1440 | 0,0       | rotate_180 | Primary ultrawide           |
| 1   | DP-2  | 3440x1440 | 0,1440    | normal     | Secondary UW (`mainScreen`) |
| 2   | DP-1  | 1920x1080 | 3440,1440 | rotate_270 | Vertical, 165 Hz            |

This is the **desktop** set. The laptop's heads (`HDMI-A-1` 4K, `eDP-1`, and a
`DP-5`/`DP-1` dock variant) sit **commented out above it** in the same block — one
repo serves both machines, so switching is uncommenting one group and commenting
the other, then `Super+Shift+r`. A head that isn't connected is simply ignored,
but leaving both groups live would give the same name two entries.

Every entry needs an explicit `.x`/`.y`. The defaults are `-1,-1`, which reach reads
as "don't send `set_position`" — river then auto-places the head wherever it likes
(it put HDMI-A-1 side-by-side with eDP-1, not above it). The laptop's external sits
past x=5000 so it never collides with the desktop's DP block.

**Env vars (set by reach `.env` block):** `XDG_CURRENT_DESKTOP=river`, `XDG_SESSION_TYPE=wayland`, `QT_QPA_PLATFORM=wayland`, `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus`, `PROTON_ENABLE_WAYLAND=1`, plus an explicit **`PATH`** and **`XDG_DATA_DIRS`** that put `~/.nix-profile` first — greetd doesn't reliably hand the nix profile down (it differs between the desktop and the laptop), so without them a bind spawning a nix-installed binary silently does nothing. Note this `XDG_DATA_DIRS` is nix-**first**, while `home.nix`'s `home.sessionVariables` copy is nix-last; reach's is the one a session actually gets. Does **not** set `QT_QPA_PLATFORMTHEME`/`QT_STYLE_OVERRIDE` (old dwl setupenv did) — re-export if Qt apps stop picking up qt6ct/Kvantum.

**Autostart** (`de/.config/reach/autostart.sh`) is minimal — most daemons moved to runit user services. It: pins `DBUS_SESSION_BUS_ADDRESS` to `$XDG_RUNTIME_DIR/bus`, starts `runsvdir $HOME/.local/sv` if not running and waits for the bus socket, launches `kitty --class rmpc rmpc`, and `dconf load`s `~/.config/dconf/interface.dconf` into GNOME settings.

**Window rules** (match `app_id`/`title`; `^foo`=starts-with, `foo`=contains; **`desktop` = 1-based number**, not the old `tags` `1<<n` bitmask; `switchto` replaced `switchtotag`; `monitor`=array index): rmpc→desktop 1 on mon 2 (DP-1), zen→desktop 3 + switchto, signal→desktop 4, `^steam`→desktop 5, `^float`/pavucontrol→floating centered 50%×50%.

**Status bar** — **gone from reach entirely**. The bar is quickshell's (`Bar.qml`); `bar.zig`, the in-process someblocks engine (`status.zig`), `render/` (fcft/pixman glyph rasterization) and the whole `.bar` config block were deleted, ~1.4k lines. `.bar = .{ ... }` in config.zon is now an **unknown key** — and an unknown key fails the whole ZON parse, dropping reach to compiled-in defaults (no binds, no monitor layout). Two consequences worth remembering: the old `enabled = false` line had to come *out of* config.zon **before** installing the new binary (a removal is accepted by both), and with an *old* binary a reload now turns the bar back **on**, since a dropped field reverts to its compiled-in default (which was `true`). `Output.usableArea()` no longer subtracts anything — a panel's exclusive zone reaches the layout through river. SIGHUP reload survived the deletion in `src/signals.zig`; it used to ride the status engine's SIGRTMIN signalfd, so `kill -35`-style block refreshes are gone with it. reach no longer links fcft or pixman (borders are single-pixel buffers), and the overlay ebuild's RDEPEND dropped both.

**State socket** (`src/ipc.zig`, new) — reach publishes what its bar used to draw, since nothing about desktops/focus/titles is reachable any other way: river is non-monolithic, reach *is* the WM, and there is no compositor-side workspace protocol for a panel to bind. A SOCK_STREAM unix socket at `$XDG_RUNTIME_DIR/reach.sock` emits one JSON line per **change**, each a *complete* snapshot (`{"desktops":9,"brightness":100,"temperature":4000,"outputs":[{name,desktop,focused,fullscreen,occupied[],title,appId}]}`; the two gamma fields are what let the panel drop its `gdbus monitor`) — whole snapshots, not deltas, so a reconnecting client needs no resync and can't apply anything out of order. Published from the render cycle, the same beat that redrew the internal bar; composing is skipped entirely when no client is connected. **Deliberately write-only**: client fds are read only to notice a disconnect. A `view <n>` command for clickable desktop cells would have to name the output too — `action.view` acts on `query.selectedOutput()`, so a click on an unfocused monitor's bar would switch the focused one — and moving the selection is a focus-semantics decision, not one a status socket should make.

**Keybinds:** `Super`=Mod. A `.binds` block **replaces the entire** default action/spawn/chord keymap **except** the auto-generated per-tag digit binds (`Super`/`+Ctrl`/`+Shift` + `1`–`9` = view/toggle/move, never listed in config). See `config.zon` for the full map. Notable: launchers (`Super+Tab` kitty, `Super+BackSpace` floating kitty, `Super+Space` quickshell launcher (`qs ipc call launcher toggle`, replaced rofi), `Super+Shift+Escape` shell settings (`qs ipc call settings toggle`), `Super+t` zen, `Super+w` rmpc / `Super+Shift+w` rescan, `Super+V` clipboard history (`qs ipc call clipboard toggle`, replaced clipfzf), `Super+X` killfzf, `Super+Z` svfzf, `Super+Shift+Z` ssvfzf), two-key chords: `Super+r` = apps (`d` legcord, `b` brave, `s` steam, `a` audio mixer, `n` network menu — which is also where the VPNs are), `Super+s` = screenshots (`s` quick, `d` section, `0`–`3` a whole output each), `Alt+[` cycle EQ sink, `Alt+Up/Down` volume, `Alt+Left/Right` mic, `Alt+End` mic mute, `Super+Alt+Left/Right` brightness (in-process `.brightness` action, no script), night light via `.gamma.temperature` + reload rather than a key, `Super+P` lock (`qs ipc call lock lock`; the lock screen also carries poweroff/reboot/logout), `Super+b` random wallpaper (`qs ipc call wallpaper random`), `Super+Shift+b` wallpaper picker (`qs ipc call wallpaperpicker toggle`).

## Quickshell Desktop Widgets

**Config:** `de/.config/quickshell/` — QML components + `scripts/` (data providers). Entry point: `shell.qml` (`ShellRoot`), where each feature is one `LazyLoader { active: Config.on("<key>"); <Component>{} }` line — a feature toggled off is **never built** (zero RAM, no daemon), and toggling one at runtime builds or tears it down live, no restart. `active:` is synchronous on purpose (an all-`activeAsync` shell would never load — async loading needs an existing window first). Written in QML/Qt Quick; no separate daemon/open split — `qs` runs in the foreground and runsv supervises it directly.

**Which features are on is per-machine state, not config.** `Config.qml` holds a **catalogue** (`features`: one `{key, group, label}` entry per feature, in menu order) and nothing else; the on/off values live in `~/.local/state/quickshell/features.json`, which is **outside the repo** — not stowed, not committed — so one config serves the desktop and the laptop and each keeps its own set. **Only the OFF switches are stored**: anything absent is on, a missing file means the whole shell, and deleting the file restores everything. Edit it through the settings menu (`Super+Shift+Escape` / `qs ipc call settings toggle`), not by hand — hand-edits only land on the next start or QML reload. Adding a feature is one catalogue entry plus one `shell.qml` line; the menu is generated from the catalogue, so there is no second list to keep in sync.

**Service:** `~/.local/sv/quickshell/run` — waits for dbus+wayland sockets, sets `QT_QPA_PLATFORM=wayland`, `exec qs`. It also sets `QT_QUICK_BACKEND=software` (see **Rendering** below). Unlike eww, no monitor/scale detection in the shell script — that logic lives in `Config.qml` (`DP-2` present → scale 1.0, else 0.85).

**Components (shell.qml, gated by Config flags):** `WallpaperView` (per-screen wallpaper, replaces awww), `WallpaperPicker` (thumbnail grid, `Super+Shift+b`), `NotificationPopups` (toasts, replaces mako popups), `Session` (idle+lock screen, session actions on it; replaces swaylock+swayidle), `Clipboard` (cliphist text+image watchers, replaces the runit cliphist service), `ClipboardPicker` (history picker, `Super+V`, replaces clipfzf), `Clock`, `CpuGraph`, `NetGraph`, `Mpd`, `Weather`, `Notifications` (history panel + DND, top-right, height follows its content), `Calendar`, `Brightness`, `Battery` (laptop low-charge warning), `Osd` (transient volume/mic/brightness/sink indicator), `Spotlight` (shake-to-find cursor), `Launcher` (drun app launcher, replaces rofi), `Network` (Wi-Fi + VPN menu, replaces nmtui — and the VPN half replaced the old bottom-left `Vpn` card; there is deliberately no separate VPN menu, since this one already lists the tunnels), `Bar` (the status bar, replaces reach's baked-in one), `Audio` (sink/source + per-app mixer, replaces pulsemixer), `Settings` (feature switchboard — the one component with no flag, since disabling it would leave no way back). The `tray` flag has no component of its own: the system tray is a section of `Bar.qml`.

**Shared pieces** (what a new widget should reach for before writing its own):
- `Config.qml` — besides the feature catalogue: `Config.scale` / `Config.s(n)` (the one 0.85-on-laptop factor; `Widget` forwards `s()` so cards call it unqualified) and `Config.screen(name)` (the output or null — the "which monitor" loop used to be open-coded in four places).
- `Theme.qml` — the palette plus `rowSelectBg`/`rowSelectFg`, the picker's selected-row colours that four files had spelled out as `#11111b`/`#bac2de`.
- `Widget.qml` — the card chrome (pin to the main screen, flat border, padding, Bottom layer). `Txt.qml`, `HeaderBtn.qml`, `Graph.qml` are the small shared visuals.
- `Poll.qml` — Timer+Process+StdioCollector in one. `onData` gives raw stdout; **`onJsonData` gives parsed JSON or null**, which is what the four JSON-producing pollers use instead of each writing the same try/catch.
- `Picker.qml` — full-screen overlay pickers: IPC toggle, focused-monitor latching, `hoverMoved`, scale/`s()`, and the shared `rows`/`selected`/`move()`/`firstSelectable()` list navigation that steps over `kind: "header"` entries.
- `PickerRow.qml` — Settings, Audio and the two Network menus' shared row chrome: section labels, selection, current-device wash/accent and guarded hover. Pass the picker, model entry/index and row heights; supply the row content and handle `activated` (selection has already been updated). Child controls sit above the row's MouseArea so the audio slider keeps its own drag handling.
- `NetworkData.js` — pure snapshot parsing and menu data construction for `Network.qml` (both instances). The QML owns polling, state assignments and commands; the helper owns nmcli escaping, AP deduplication, VPN grouping and always-on warnings. `vpnRows()` **stamps `label` and `alwaysOn` onto each row** instead of leaving them to be re-derived by name at paint time: both are decided once, when the row is built, and a delegate that asks later has to be handed the whole list to do it. That also closed a latent collision — `warning()` used to match the always-on name across *every* row, and `buildRows` gives an eth row its connection's name, so a wired connection called `wireguard` would have counted as the homelab tunnel being up.
- `BarStatusData.qml` / `BarStatus.qml` / `BarTray.qml` — the bar's shared status sources, per-output status layout and per-output tray/menu respectively. `Bar.qml` creates one status data object for all outputs and owns their surfaces, workspace cells and titles.
- `NotificationService.qml` — the singleton that actually owns `org.freedesktop.Notifications` (replacing mako), plus the rolling 20-entry history and the DND flag. `NotificationPopups` renders `live`, the `Notifications` panel renders `history` — two widgets, one server. History is recorded even under DND (mako logged `invisible=1` notifications too).
- `Sys.qml` — CPU/RAM/disk/GPU **and the battery** (`batteryPresent`/`batteryLevel`/`batteryStatus`/`charging`). One 10s poll of the BAT0 sysfs pair serves both the bar block and the corner card, which used to poll it separately at 30s and 10s.
- `Volume.qml` — the default sink/source and their volume/muted/name, with the one `PwObjectTracker` that keeps them bound. The bar, `Mpd.qml` and `Osd.qml` each carried a copy of that block; `Audio.qml` still talks to Pipewire directly, since the mixer is about the whole graph rather than the defaults.

**Rendering:** `QT_QUICK_BACKEND=software` in the service script. The shell is flat rectangles, text and one wallpaper blit, but the GL scenegraph gives **every visible window** its own render thread and Mesa context, and there are ~15 of them (a wallpaper and a bar per output, plus one per ambient card) — 589 MB RSS / 135 threads on the AMD laptop, against 260 MB / 22 with QPainter. The cost is that GPU-only QML types silently draw nothing: no `ShaderEffect`, `layer.effect` or `MultiEffect` in here (`TrayMenu.qml` tints its icons with `QtQuick.Controls.impl`'s `ColorImage`, which recolours on the CPU, for exactly this reason). Drop the line if a wallpaper crossfade ever stutters on the 3×3440x1440 desktop.

**Notable wiring:**
- `Bar.qml` / `Reach.qml` — the status bar, one per output, replacing the one reach drew itself; same layout (`[desktops] [title … app_id] [status]`), same colours, same hide-vacant/focused-monitor-highlight rules (reach's occupied-corner box was dropped — the cell being drawn at all already says it), so the switch is invisible. `Reach.qml` is the singleton holding window-manager state from reach's socket (see **State socket** above); `forScreen(name)` is how each bar finds its own output. Non-obvious bits: (1) it is an ordinary **layer surface**, so its `exclusiveZone` reserves the strip and the compositor pushes windows *and* the other quickshell cards below it — reach's bar was a river shell surface and had to subtract itself from the layout by hand (`Output.usableArea`). (2) The socket retry is driven by `running: !sock.connected`, **not** by `onConnectionStateChanged`: a connect that *fails* never entered the connected state, so there is no state change to hear and the first attempt would be the only one — the bar would stay blank for the whole session. 5s, only to keep the log quiet (each failure logs); the normal path never retries, since reach's autostart starts runsvdir and is listening before quickshell exists. (3) Hidden (`visible: false`, which releases the exclusive zone with it) when a window is fullscreen on that output, matching reach. (4) The status side is native — volume/mic from the `Volume` singleton, battery from `Sys`, clock in QML, one `sh -c` for the default-route IP — which is what retired the six block scripts and the `kill -35`/`-36` refresh binds.
- `Spotlight.qml` — dims every output and leaves a clear, feathered circle around the pointer (PowerToys' Find My Mouse), fired by reach's shake detector. Non-obvious bits: (1) **the overlay must accept input**, because that is the only way any Wayland client can learn the cursor position — the `enter` event carries surface-local coords. So it swallows clicks while mapped, which is why it is transient and dismisses on any key, any click, or ~60px of movement, with a 4s safety timeout. (2) Movement-dismiss is armed only after a 600ms grace period: the gesture that summons it *is* the pointer moving, so without that the shake would dismiss it in the same frame. (3) Under `QT_QUICK_BACKEND=software` there is no `ShaderEffect` to punch a hole with, so the wash is four plain `Rectangle`s around a square gap plus one small `Canvas` filling that square (`destination-out` = `QPainter::CompositionMode_DestinationOut`). The Canvas image is **position-independent**, so it paints once and is only ever moved — nothing repaints a screenful of pixels on the CPU as the pointer travels.
- `Session.qml` — the lock screen *is* the power menu. `Super+P` locks (`qs ipc call lock lock`), `IdleMonitor` locks at 300s, `WlSessionLock` (ext-session-lock) + PAM unlocks — and the surface carries Power off / Reboot / Log out under the password field. Three files collapsed into this one (`Lock.qml`, `PowerMenu.qml`): a menu offering "Lock" and a lock screen offering nothing were two halves of the same thing, and the `power` IPC target is gone with the overlay. Non-obvious bits: (1) the password field **keeps focus permanently** — arrows and Tab arm an action from inside its `Keys.onPressed` rather than moving focus (Down/Right step into the row, Up/Left back out to the field), so a password typed at any moment still lands in the box it was meant for, and typing disarms (a stray Tab can't turn the next Return into a poweroff); nothing fires on one keystroke or one click, it's arm-then-confirm. (2) poweroff/reboot run `doas -n <cmd>` with the **bare** command name, matching this box's `permit nopass :wheel cmd poweroff` rule — `/usr/bin/poweroff` misses it and falls back to a password-requiring rule. They need doas at all because `/usr/bin/poweroff` (the runit-shutdown dispatcher) self-elevates with doas itself, and the old unlocked menu could spawn a floating kitty for that prompt — but the lock surface sits above every window, so the prompt would be invisible and unfocusable there. `-n` fails fast instead of hanging on a prompt no one can reach, and the surface says so rather than doing nothing.
- `Audio.qml` — `Picker`-based mixer: output devices, input devices, and a volume row per playing app (`Super+R` `A` / `qs ipc call audio toggle`; replaced `kitty --class float -e pulsemixer`). Rows are classified by `media.class`, **not** `isSink`/`isStream` — a playback stream reports `isSink` true as well, since it feeds one. App streams are those carrying an `application.name`; that is exactly what excludes the EQ filter-chains' own `effect_output.*` playback streams and the mic loopback, which must never be dragged along when streams migrate. `PwObjectTracker` stays armed on all nodes rather than being gated on `open`, because a node only publishes `.audio` while something holds a binding and the menu has to be right in the frame it opens. Picking a **sink** shells out to `flip.sh set <name>` instead of setting `Pipewire.preferredDefaultAudioSink` — the optical chain needs a card-profile flip first and existing streams need moving by hand, and that logic already lives in the script `Alt+[` uses. Sources just set `preferredDefaultAudioSource`. The current default sink/source carries a mauve wash plus a left accent bar, brightening when selected rather than being covered by the selection band — tinting only its icon was invisible under the cursor. Keys: `j`/`k` select, `h`/`l` volume ±5%, `m` mute, `Return` activate.
- `Network.qml` — `Picker`-based Wi-Fi + VPN menu (`Super+R` `N` / `qs ipc call network toggle`), replacing the floating kitty running nmtui. **This is also where the VPNs live** — a bottom-left `Vpn` card and then a separate VPN menu both came and went, because this menu already lists every tunnel and a second surface for the same rows is a second thing to keep honest. Non-obvious bits: (1) **every tunnel is an NM profile.** The lab `~/VPNs/*.ovpn` configs used to be run by `scripts/vpn-manager.sh` as a bare root `openvpn --daemon` NM knew nothing about; that needed a doas rule to start one and a *second* doas rule to kill one, scraped the profile's state out of `pgrep`+`/proc/<pid>/cmdline`, and surfaced as an *externally connected* `tun0`. When the kill rule didn't match, `disconnect` failed silently, `connect` stacked a second daemon, two tunnels ran at once on two tun devices — and each rejected `doas` counted as a failed login until the account locked for ten minutes. They are now imported (`nmcli connection import type openvpn file <f>`, which `nmcli general permissions` allows this user) and are ordinary NM connections: one code path, up/down by UUID, state from the snapshot the menu already takes, **no daemon, no script, no doas rule, nothing to scrape**. An `~/VPNs/*.ovpn` NM hasn't been given yet is **imported automatically** while the menu is open (`pendingImports` matches files against NM profiles by the name NM would give them, so an imported file is never handed over twice), which keeps "drop a lab config in `~/VPNs`" as the whole workflow. **The VPN section is a MIRROR of that directory** (plus the always-on tunnels), and it covers both kinds: **`*.ovpn` imports as openvpn, `*.conf` as wireguard** (`nmcli connection import type wireguard`), so a temporary wg config is dropped in the same place as a lab config. A file with no profile is imported, a profile whose file **changed** is deleted and re-imported, and a `type=vpn` profile with no file behind it is **deleted** — either the registry (`~/.local/state/quickshell/vpn-sources.json`) remembers the file it came from and that file is gone, or nothing has ever heard of the profile and no file would produce its name. That second case is what used to leave permanent garbage in the menu: a profile imported before the registry existed, or by hand, is in no registry to age out of. The change check is a **sha256 of the file**, recorded in the registry at import (`sha256sum` rides in the same listing poll). Name matching alone is not enough and this is not theoretical: HTB reissues a config under the same filename pointing at a new server, so `HTB-TCP.ovpn` said `dedivip-4` while the profile NM kept serving still said `dedivip-3` — every connection through the menu timed out while the very same file worked from a terminal, which is the confusing shape this takes. An entry with no stored hash predates the check; `adoptSources` stamps one on the next pass rather than re-importing on a guess. Consequence worth knowing: **an OpenVPN profile you created by other means, for a config that does not live in `~/VPNs`, will be removed** — put its name in `ALWAYS_ON` to exempt it. A WireGuard profile is only ever removed when the registry itself imported it and its file is gone — an **untracked** wireguard profile is left alone however it got there, because it holds a private key that may have no other copy, whereas an openvpn profile can always be rebuilt from its file. For the same reason a wireguard import is a bare `con import` with **no** `con mod` chained on: unprivileged, that drops the key it just stored. A wg tunnel takes its routes from `AllowedIPs`, so if one carries `0.0.0.0/0` and you want it split, that is a one-off `doas nmcli con mod <uuid> ipv4.never-default yes`. Both halves are gated on `filesSeen`, a listing that actually succeeded, so an unreadable `~/VPNs` can never read as "delete everything". **The import also sets `ipv4.never-default`/`ipv6.never-default` on the new profile, in the same command** — HTB pushes `default via <tun gw> metric 50`, which outranks the Wi-Fi default (metric 600), so without it every packet including DNS goes down a tunnel that carries no general internet and the machine drops off the network the instant a lab connects. `never-default` discards only that default; the lab subnets it also pushes (10.10.x, 10.129.x, 10.13.37/38) keep their routes. These are lab configs by definition, so split tunnel is the policy. The UUID comes from the import's own stdout, never a name lookup, and stdout is reprinted so the registry's own UUID match still sees it. The import goes through the same `run()` queue as user actions — two nmcli writes at once, or an import stomping the status line mid-connect, is the only way it could be worse than the manual step — and **three guards** keep it from making duplicate profiles, each answering a different question. (a) `importTried`, cleared on open: stops a file NM refuses from retrying every 5s and owning the status line, while still letting it succeed on the next open once the plugin is there. (b) `importDone`, never cleared: `nm.refresh()` is asynchronous, so for a second or two after an import `conns` still lacks the new profile — close and reopen the menu in that window and the name match says "missing" again. (c) `nmSeen`: **no import before the first nmcli snapshot has landed.** The file listing and the snapshot are independent polls and the listing usually wins, so with `conns` still empty every profile NM already has looks un-imported. That one produced exactly one duplicated profile per cold start — the first file in the list — because the import's own refresh corrected the snapshot before the next file was considered. The openvpn plugin's descriptor is at **`/usr/lib/NetworkManager/VPN/nm-openvpn-service.name`** (not `lib64`). Needs **`net-vpn/networkmanager-openvpn`**; without it `con import` fails with `unknown VPN plugin`. (2) The homelab tunnel — the NM `wireguard` profile, from the root-only `/etc/wireguard` config — is named in one `ALWAYS_ON` list in `NetworkData.js`. **That profile is currently absent** (deleted 2026-09-13; the tunnel moved to the defguard client, which NM doesn't own), so as of now `ALWAYS_ON` matches nothing: no Homelab section, no down-warning. The list, and the routing note below it, describe how it behaves when an NM profile by that name exists (by NM *connection* name, the only name the rows carry); it gets its own section, a red **down** marker, and the warning line. The `~/VPNs/*.ovpn` profiles are HackTheBox/TryHackMe labs and fall into "Labs". **The two overlap in 10/8 and the lab wins by default:** the homelab peer's `allowed-ips=10.0.0.0/8` installs one `10.0.0.0/8 dev wireguard metric 50` route, while HTB's openvpn pushes `10.10.8.0/22 via 10.10.14.1 dev tun0` — which *contains* the homelab's own `10.10.10.0/24`, and longest prefix beats metric, so with a lab up every homelab packet goes down the lab tunnel (`ip route get 10.10.10.1` names the device that actually wins). The profile therefore carries an explicit `ipv4.routes 10.10.10.0/24`, a longer prefix than the lab's /22. The cost is that HTB's legacy 10.10.10.x machines are unreachable while the homelab is up — `nmcli con down wireguard` for those. DNS needs no tunnel: homelab names are public records under `zarz.org`, so the profile's `ipv4.dns` is deliberately `1.1.1.1,1.0.0.1` and `ipv4.dns-priority=-50` is there only to stop eduroam's DHCP resolvers from replacing that list. The route edit is a `doas nmcli con mod <uuid> +ipv4.routes 10.10.10.0/24`: unprivileged `con mod` on a system connection silently destroys the stored private key. **Enter only ever connects, `d` disconnects**, for every row kind: toggling on Return put the always-on tunnel one stray keystroke from being dropped. (3) Nothing elevates — `con up`/`con down`/`device wifi connect` and `con import` are all fine unprivileged (`nmcli general permissions` lists `settings.modify.system` as yes). The menu runs `con mod` in exactly one place, the import above, and only against a profile it created one line earlier: unprivileged `con mod` drops a profile's stored secrets, but a fresh openvpn import has none — the certs are extracted to `~/.local/share/networkmanagement/certificates/nm-openvpn/*.pem` and referenced by PATH, so `vpn.secrets` is empty. Never `con mod` an existing profile (that is what destroys the wireguard private key). (4) NM connections are acted on by **UUID**, never by name (`con up id <name>` is ambiguous — several connections may share a name), and a VPN row whose *device* reads `connected (externally)` is labelled **external**: that is NM describing a `wg-quick` link it merely assumed, backed by a volatile profile in `/run`, not a profile you saved. (5) Joining is `nmcli device wifi connect <ssid>`, **never** by connection name: eduroam's profile is named `eduroam [a8f5604d]`, so name-matching would miss it and create a second profile. NM asks for a key by *failing*, so a secrets error grows a password field in the bottom bar and retries once (the key rides in argv — nmcli takes it no other way). (6) Connections, devices and the radio switch share one tagged `sh -c` (~25ms) because they're one snapshot and separate timers show a torn one — but **the AP list is deliberately not in it**. `nmcli device wifi list` defaults to `--rescan auto`, which **blocks ~3.4s** whenever the scan cache is over 30s old (24ms when fresh), and as the last command in the shared `sh -c` it held the whole snapshot back: an open with a cold cache drew a menu with no Wi-Fi *and* no wired rows, leaving only the rows from the separate `~/VPNs` listing. So it's its own `Poll` with `--rescan no` (cache read, always instant), and the scan request goes out detached on a 15s timer, with the next tick collecting the results. All polls are `running: root.open`, so a closed menu costs nothing. nmcli's terse output escapes `:` as `\:`, so the parser unescapes rather than plain-splitting.
- `FileIndex.qml` — the corpus and ranking behind the launcher's `/` file mode; deliberately **not** a shell-out to `fd | fzf`, because both halves of that pipeline are wrong here. (1) **The corpus.** Anything that follows symlinks (`fzf`'s default walker, `find -L`, `fd -L`) leaves $HOME through `.nix-defexpr/channels` and `.local/state/nix/profiles` into `/nix/store` — $HOME goes from ~46k entries to **3.6M**, nearly all duplicate nix channel trees, and a `fd -L` over it doesn't finish in two minutes. `fd` without `-L` plus the `excludes` list (caches, Steam, the stowed `icons`+`fonts` themes at ~95k files between them) gives ~46k entries in ~0.1s. (2) **The match.** fzf scores a subsequence anywhere in the *whole path*, so "home-manager" matches `.../home-manager/po/tok.po` — the query hit the directory and the file it returned was unrelated. Here a query matches the **basename**; a `/` in the query splits it, and the part before must be a plain **substring of the directory** (subsequence-matching a path is all noise). Literal tiers (exact / prefix / word-start / substring) rank above subsequence-fuzzy, which is span-capped and needs 4+ chars, and a leading `.` is stripped from the basename so `zshrc` finds `.zshrc`. Depth, hidden segments and a `demoted` list (`.local/share`, `site-packages`, `Music`, `Downloads`) are penalties, not exclusions. **Symlink dedupe:** stow gives every config two names (`~/.config/home-manager` is a link to `~/dotfiles/de/.config/home-manager`), and **89 of this tree's 115 symlinks** are that kind of duplicate, so a second `fd --type l ... -x sh -c 'printf "%s\t%s" "$1" "$(readlink -f "$1")"'` pass runs **first** and the main walk drops any link whose target it also indexes (46,332 -> 46,244 entries, build 0.7s -> 0.9s). The **link** is dropped, not the target: fd never descends a symlink, so the link side has no indexed children while the target side has all of them — keeping the target is what makes a parent and its contents agree about where they live. Non-obvious bits: **(a)** the index (lowercased basename/path, precomputed penalties) is built once per enumeration — lowercasing 46k paths per keystroke is the entire cost of a naive filter; **(b)** **incremental narrowing** — candidacy (subsequence) is monotone in the query, so each further character is scored only against the previous survivors: ~50-130ms for the first keystroke of a query, ~1ms after, which is why the launcher debounces 40ms and why backspace (non-monotone) re-scans; **(c)** candidacy is deliberately the *loosest* rule even when the score then rejects the entry — gating the pool on the score would make it non-monotone and silently drop matches as you type; **(d)** a native `indexOf` on the query's first character guards the JS subsequence loop, since nearly all 46k entries are misses and this keeps the cold scan a memchr rather than an interpreter loop; **(e)** hits are packed as `score * 1e6 + index` into one numeric array — 46k `{score, index}` allocations per keystroke was most of the cost; **(f)** the index is built on first entering `/` mode and **released 60s after the launcher closes** (~10 MB of JS strings), which is also what keeps it from going stale, since a rebuild is only ~0.1s of `fd`.
- `ClipboardPicker.qml` — `Picker`-based clipboard history (`Super+V` / `qs ipc call clipboard toggle`), replacing the floating kitty that ran `clipfzf` (**that script is deleted**; it is named below only to explain what the QML does differently). Rows come from one `cliphist list` per **open** — never polled, because a closed picker should cost nothing — and typing filters them by substring. Enter copies (`cliphist decode <id> | wl-copy`), `Ctrl+D` deletes the entry and re-lists. Non-obvious bits: (1) an image entry is recognised from the **list line** (`[[ binary data 40 KiB png 1362x367 ]]`), so nothing is decoded to find out what an entry is; clipfzf decodes each highlighted row and asks `file` for its mime type, because fzf hands it no other hook. (2) The preview decodes lazily behind a 60ms debounce (holding `j` must not spawn a decode per row it passes) and memoizes per id — text through `head -c 4000` into a string, an image into `$XDG_CACHE_HOME/quickshell/clip/<id>.img` because an `Image` needs a file. That was the hard half in the terminal: clipfzf can only draw one by shelling `kitten icat` in unicode-placeholder mode, the one mode that survives fzf's redraws, and only because it always runs inside kitty. (3) The preview `Image` is `sourceSize`-capped to the pane and `cache: false` — capped because **under `QT_QUICK_BACKEND=software` every pixel is decoded and scaled on the CPU**, so a full-resolution screenshot would otherwise be a few hundred MB of pixmap for a 600px pane; uncached because a `cliphist wipe` restarts ids at 1, so a path can come back around holding different bytes (the memo is cleared per open and the decoded files are purged once at startup for the same reason). (4) `wl-copy` forks a daemon to serve the selection, so it has to outlive the call — `Quickshell.execDetached` is that. clipfzf's `>/dev/null 2>&1` on the copy exists only because that daemon inherited kitty's pty and kept the window open; there is no pty here.
- `Osd.qml` — transient indicator for volume / mic / brightness / default-sink changes. The gap it filled: the only feedback for `Alt+Up/Down`, `Alt+Left/Right` and `Super+Alt+Left/Right` was the bar, which lives on one monitor — press a key while looking at another and nothing visibly happened; `Alt+[` (flip.sh) was worse, since the only way to learn where audio went was to play something. Non-obvious bits: (1) it draws on **every** output, not the focused one — reach names no focused monitor over IPC and the pointer-containment trick `Picker.qml` uses needs a full-screen surface, which would swallow clicks for as long as it's mapped; each OSD window is only as large as the indicator and only mapped while shown, so it never eats input. (2) **Nothing polls** — volume/mic ride the `Volume` singleton's properties (Pipewire's own signals underneath), brightness is a property change on the `Reach` singleton (reach publishes it on its socket; this is what retired the `gdbus monitor` subprocess), and the sink label falls out of `Volume.sink` changing identity.
- `WallpaperPicker.qml` — `Picker`-based category sidebar + thumbnail grid (`Super+Shift+b` / `qs ipc call wallpaperpicker toggle`). Tiles come from `~/.cache/wallpaper-thumbs`, **never** the originals — decoding a 22MB 7264x4096 PNG per tile is what makes a previewer peg every core (it's why yazi's spun the fans). `~/.local/bin/wallpaper-thumbs` renders them and `--list` emits `category<TAB>source<TAB>thumb`, so the naming rule lives in that script and nowhere else; the picker re-runs it on every open (~35ms warm) so wallpapers added since last time appear. The `;` between render and list is deliberate — a failed render still lists what's there. Source dimensions are memoized per path so revisiting a tile never re-probes.
- `Wallpaper.qml` / `WallpaperView.qml` — singleton; `IpcHandler` target `"wallpaper"` → `random` or `set <path>`; `Super+b` = `qs ipc call wallpaper random`; picks from `~/Pictures/bgs`. **RAM-critical:** the `Image` layers use `cache: true` + a single shared `sourceSize` (`Wallpaper.decodeSize`, the global max output WxH) so **all outputs share ONE decoded buffer** via `QQuickPixmapCache` — do **not** set `cache: false` or per-output `sourceSize` (that's what made every monitor hold its own copy, ~114 MB). The two crossfade layers free their source once faded out, so steady state holds a single buffer. GPU textures are still per-window but live in VRAM (nvidia), not RSS.
- `Clipboard.qml` — `Scope` with two self-restarting `Process` watchers (`wl-paste --type text/image --watch cliphist store`); inherits qs's `WAYLAND_DISPLAY` (no socket-wait needed). Replaced the runit `cliphist` group service. The picker half is `ClipboardPicker.qml` now, not `clipfzf`.
- `NotificationPopups.qml` — uses `Quickshell.Services.Notifications` (FreeDesktop D-Bus server). `de/.local/share/dbus-1/services/fr.emersion.mako.service` is a stub (`Exec=/bin/true`) that shadows the system mako activation file — prevents D-Bus from relaunching mako when qs restarts and momentarily drops the `org.freedesktop.Notifications` bus name.
- `Battery.qml` — bottom-right card, a companion to the bar's `battery` block (the bar does its own red via `^fg()` markup; this adds the toast and an at-a-glance gauge). Reads `/sys/class/power_supply/BAT0` on a 10s timer (**upowerd is not running**, so `Quickshell.Services.UPower` reports nothing). Below 20% while discharging the readout+gauge+border turn red and one `notify-send -u critical` fires — latched, re-arming only above 25% or on charge, so a level hovering on the threshold can't spam it. **Two non-obvious bits:** (1) `stackLayer` is state-dependent — `Bottom` at rest like the other ambient cards, `Overlay` once low, because a Bottom-layer card is hidden behind any tiled window at exactly the moment it needs to be seen; (2) the `shell.qml` gate is `Config.battery && Config.batteryPresent`, where `batteryPresent` is a `blockLoading` `FileView` probe of `BAT0/capacity` in `Config.qml` — so the desktop never *builds* the widget rather than building it and hiding it.
- `Brightness.qml` / `Sys.qml` / `CpuGraph.qml` — `Brightness` is a **readout, not a control**: reach owns gamma and publishes the level, so the card binds to `Reach.brightness` (no `brightness.sh get` poll, no subprocess) and the drag-to-set slider is gone, because the state socket is write-only and there is nothing for a drag to call — `Super+Alt+Left/Right` is the way to set it. Then CPU/RAM/disk + nvidia-smi GPU; `/proc/net/dev` + `ip -j addr` for net. `Sys` gates two things on a one-shot probe rather than rediscovering them per tick: the GPU read on `/proc/driver/nvidia/version` (on the laptop the 2s tick forked an `nvidia-smi` that can only fail, ~43k times a day) and the battery timer on the first BAT0 read (the desktop reloaded two files that don't exist every 10s).
- `Mpd.qml` — **fully native, no subprocess polling**: transport/metadata/art/progress via `Quickshell.Services.Mpris` (follows the active MPRIS player, prefers a playing one then MPD — so it also drives Zen etc.; needs the `mpd-mpris` bridge in the `mpd` group service to put MPD on the MPRIS bus), volume/mute via `Quickshell.Services.Pipewire` (`defaultAudioSink`/`defaultAudioSource` + a `PwObjectTracker` to keep `.audio.volume`/`.muted` live). Replaced the old `mpc`×4/s + `wpctl`×2/s polling.
- `Calendar.qml` — ICS agenda list in the left bar (reads `calendar.url` via `calendar.sh events`).
- `Settings.qml` / `Config.qml` — the feature switchboard and its UI. `Config.overrides` is parsed from the state file by an **initial binding, not `Component.onCompleted`**: the first thing to touch the singleton is `shell.qml`'s `active:` binding, and `onCompleted` runs *after* that read — every disabled widget would be built and then immediately torn down. As a binding the first answer is already correct. `FileView` is `blockLoading` for the same reason (the flags are read in the frame the shell builds), `printErrors: false` because a missing file is the normal first-run state, and it creates its own parent directory on first write. Writing through `Config.setEnabled()` **replaces that binding for good**, which is deliberate: `setText()` is async (`text()` still returns the old value in the same tick), so a value bound to the file would fight every toggle — the menu owns it from then on. Toggles assign a fresh object rather than mutating, since QML only notifies on assignment and every `LazyLoader` is watching. A corrupt file logs and falls back to everything-on rather than taking the shell down.
- `Picker.qml` — shared base for the full-screen pickers (`Launcher`, `WallpaperPicker`, `Audio`, `Network` ×2, `Settings`): IPC toggle, one overlay per output, the focused-monitor pointer-latching, and **`hoverMoved(item, event)`**. It also owns what four pickers each used to re-type: `boxHeight` summed from `rows` (`headerHeight`/`rowHeight`/`barHeight`/`minBoxHeight`; a picker with no `rows` falls back to `heightFraction`, which is what `0` means), **`navKey(e)`** (Escape/Return/j/k/arrows — a picker handles only its own extra keys, and Return goes to its `activate(i)`), the `onRowsChanged` re-clamp of `selected` (Audio has the shell's most volatile rows and never had one), and taking keyboard focus — so `reset()` on the content now means only "my own extra state" (a query to clear, a password field to drop). The content `Loader` is **gated on the box being visible**: ungated, every picker's tree existed on every output for the whole session, and the wallpaper grid held its decoded thumbnails in all three. Every picker's list asks `hoverMoved` before letting hover take the selection, because Qt delivers a hover move whenever the row *under* the cursor changes — so neither `entered` nor `positionChanged` means the user pointed at anything. Arrowing through a list scrolls it past a motionless pointer, and the row that slides underneath fires hover and hands the selection straight back (arrow down once, jump back to wherever the mouse is). `hoverMoved` compares **window-space** coordinates and is true only on real movement. `pointerSeen` is cleared on open so the first event merely records a baseline — an overlay maps under wherever the cursor already is, and without that `Super+Space` `Return` would launch, or the audio menu would switch a sink, that nobody pointed at. `Launcher` and `WallpaperPicker` both scroll via `positionViewAtIndex` and had the full bug; `Audio` doesn't scroll but had the open-under-cursor half.
- `Launcher.qml` — minimal drun app launcher (replaces `rofi -show drun`). Opens on the **focused monitor**: a full-screen overlay is mapped per output (`Variants` over `Quickshell.screens`), but the box is drawn only on the output whose overlay contains the pointer — under reach's `sloppy_focus` that IS the focused monitor. reach exposes **no IPC** for the focused output and grants keyboard focus to *every* layer surface, so pointer containment (a `hoverEnabled` MouseArea latching `activeScreen`) is what singles one out; `activeScreen` is blanked on open (150ms DP-2 fallback timer) to avoid flashing on the previously-focused monitor. Shared query/results/selection state lives on the `Scope` root. The filtered list is a **binding**, never a snapshot: `DesktopEntries` scans asynchronously (`applications.values` is empty at load and fills ~50ms later), so a list computed once when the box opened stayed empty for that whole open if you hit `Super+Space` right after a start or hot-reload — the symptom was an open launcher with a working query field and no rows. An empty result now says so ("no applications found" / "no matches") instead of rendering a blank box. Type to filter `DesktopEntries.applications` by name; Up/Down or Ctrl+K/J to move, Enter = `entry.execute()`, Esc / click-outside closes. Hover selection goes through `Picker.hoverMoved` (see the `Picker.qml` entry). Triggered by `IpcHandler` target `"launcher"` (`toggle`/`show`/`hide`); `Super+space` = `qs ipc call launcher toggle`. A query starting with **`/`** switches it to file mode (see `FileIndex.qml`): Enter opens the hit in `kitty -e nvim` (a directory in `yazi` — nvim on one lands in the netrw that nvim-tree disables), `Shift+Enter` always opens `yazi` (on a file: its parent, with the file selected), `Ctrl+Enter` hands it to `xdg-open`, `Ctrl+T` opens `kitty --directory` in the containing directory, `Ctrl+Y` copies the path. yazi is launched as `kitty -e zsh -ic 'y "$1"; exec zsh'` rather than as kitty's command, so `q` leaves an interactive shell (in the directory yazi was left in, via the zshrc `y` wrapper's `--cwd-file`) instead of closing the window.

**Scripts** (`de/.config/quickshell/scripts/`): `calendar.sh` (Python; `events` = agenda list, `week [offset]` = grid geometry, `refresh`, `status`; needs `icalendar`+`recurring_ical_events` from home-manager; caches to `/tmp/eww-calendar.ics`. It **globs** the nix-profile site-packages version rather than pinning it — the path was hardcoded to `python3.13`, and when nix moved to 3.14 every command silently returned `[]`), `vpn-manager.sh` is **gone**: the lab tunnels are NM profiles now, so there is no root openvpn daemon to start, find or kill (see `Network.qml`).

**Editing a `.js` library needs a real restart.** Quickshell hot-reloads QML on change, but a `.pragma library` file (`NetworkData.js`) stays cached in the running engine: new functions read as `TypeError: Property 'x' ... is not a function` even though the file on disk is correct and every `Configuration Loaded` looks clean. `SVDIR=~/.local/sv sv restart quickshell` is the fix — a QML-only edit does not need it.

**IPC gotcha:** `qs ipc call <target> show` collides with the `qs ipc show` subcommand — the CLI prints the target listing, exits 0, and never calls the handler. **`hide` and `toggle` are fine** (measured: `qs ipc call settings hide` reaches the handler; `… show` prints the listing). `Picker` therefore exposes only `toggle`/`hide`, and `Spotlight` uses `flash`/`dismiss`.

**Deps:** nvidia-smi, curl, python3+icalendar+recurring-ical-events. (`jq` went with the ports card.) (Mpd.qml no longer shells out to `mpc`/`wpctl` — it uses native Mpris + Pipewire; it does rely on an MPD→MPRIS bridge being on the bus.)

## Services (runit)

Two scopes, managed by `svfzf` (user, `Super+Z`) / `ssvfzf` (system, `doas`) or `sv` directly.

**User** (`~/.local/sv`, supervised by per-user `runsvdir` from reach autostart; disable = drop a `down` file): `dbus` (persistent user D-Bus **session** bus — whole stack inherits it), `pipewire` (**group service**: pipewire + wireplumber + pipewire-pulse), `mpd` (**group service**: mpd + mpd-mpris), `quickshell` (widgets + wallpaper + lock + notifications + **clipboard/cliphist watchers**), `syncthing`. Manage via `svfzf` or `SVDIR=~/.local/sv sv <cmd> <name>`. **Group services** run several related daemons from one `run` script (`wait -n` → kill the group → runsv respawns all together), so a crash of any one restarts the set as a unit. (Clipboard capture used to be a standalone `cliphist` group service — now owned by quickshell's `Clipboard.qml`.)

**System** (`/etc/sv` → `/service`, **outside this repo**, not stowed): enable/disable via the `/service` symlink. Inspect on-box; typically greetd/tuigreet, ufw, bluetooth, dbus, udisks2.
